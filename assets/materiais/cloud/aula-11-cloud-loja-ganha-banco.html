Dados no código

Uma retomada rápida do estudo dirigido e o problema que a aula de hoje resolve.

RELEMBREAula 10

Armazenamento distribuído

O S3 guarda cada objeto em pelo menos três zonas antes de confirmar a gravação. Durabilidade é o dado não se perder; disponibilidade é conseguir lê-lo agora. Arquivos frios mudam de classe por uma regra de ciclo de vida.

exemplo
durabilidade     11 noves: o dado existe?
disponibilidade  99,99%: consigo ler agora?
consistência     S3 é forte: gravou, leu a versão nova

logs/  dia 30 -> Standard-IA
       dia 90 -> Glacier Flexible
       dia 365 -> expira
CuidadoDurabilidade alta não é backup: apagar o objeto apaga todas as cópias.
Fase 1-1 · Diagnóstico da Aula 10

Três perguntas rápidas sobre o estudo dirigido

  • a) Um disco queimou e o arquivo continua lá. Durabilidade ou disponibilidade?
  • b) Fotos do catálogo, vistas o dia todo. Qual classe?
  • c) Logs com 2 anos, guardados por auditoria. Qual classe?

a) durabilidade: as outras cópias mantiveram o dado.

b) Standard: acesso constante, sem taxa de recuperação.

c) Glacier Deep Archive (ou Flexible): quase nunca lidos, a espera para recuperar é aceitável.

FASE 1-2 · CONTEÚDO NOVO

SQL e NoSQL

Dois jeitos de organizar um banco, cada um com o seu ponto forte.

CONCEITOAula 11

Banco relacional (SQL)

Os dados ficam em tabelas com colunas fixas, ligadas por chaves estrangeiras, e são consultados com SQL. O esquema é definido antes, e o banco garante as regras: tipos, relacionamentos, transações.

Pense assimUma planilha com colunas travadas: toda linha precisa ter os mesmos campos, e uma aba aponta para a outra.
exemplo
produtos                    categorias
id | nome     | cat_id      id | nome
1  | Camiseta | 10   ---->  10 | Blusas
2  | Calça    | 20   ---->  20 | Calças

SELECT p.nome, c.nome FROM produtos p
JOIN categorias c ON c.id = p.cat_id;
CuidadoNa AWS, banco relacional gerenciado é o RDS (MySQL, PostgreSQL) ou o Aurora.
CONCEITOAula 11

Banco NoSQL

"Not only SQL": bancos que não usam o modelo de tabelas relacionadas. Cada registro pode ter campos diferentes, o acesso é quase sempre pela chave, e o banco foi feito para crescer espalhando os dados em muitas máquinas.

exemplo
{ "id": 1, "nome": "Camiseta básica",
  "preco": 39.90, "tamanho": "M" }

{ "id": 4, "nome": "Boné",
  "preco": 49.90, "cores": ["preto", "azul"] }

mesma tabela, campos diferentes: tudo bem
Pense assimUm arquivo de pastas etiquetadas: você acha a pasta pela etiqueta, e cada pasta guarda os papéis que precisar.
Fase 1-2 · Comparação

Não é um contra o outro: muitos sistemas usam os dois. Fonte: AWS, "What is NoSQL?".

O DynamoDB é chave-valor e também guarda documentos: cada item é um conjunto de atributos, que podem ser listas e mapas.

Fase 1-2 · Qual escolher?

Relacional ou NoSQL para cada caso?

  • a) O carrinho de cada visitante: lido e gravado o tempo todo, sempre pelo id da sessão.
  • b) O fechamento contábil do mês, cruzando vendas, notas e devoluções.
  • c) O catálogo da loja: busca por id, produtos com campos diferentes.

a) NoSQL (chave-valor): acesso pela chave, muito volume, resposta rápida.

b) Relacional: precisa de JOIN entre tabelas e de transações confiáveis.

c) NoSQL (documento ou chave-valor): é o caso da loja de hoje.

FASE 1-3 · CONTEÚDO NOVO

Partição e consistência

Como um banco NoSQL espalha os dados em muitas máquinas, e o que isso muda na leitura.

CONCEITOAula 11

Partição

O banco divide os itens em partições, pedaços guardados em máquinas diferentes. Uma função hash aplicada à chave decide em qual partição cada item fica. Por isso achar um item pela chave é rápido, não importa o tamanho da tabela.

Pense assimO arquivo da escola dividido por letra do sobrenome: para achar "Silva", ninguém abre a gaveta do "A".
exemplo
hash(1) -> partição A
hash(2) -> partição B
hash(3) -> partição C

GetItem(id=2)
  1. calcula hash(2)
  2. vai direto à partição B
  3. não olha as outras
CuidadoSe quase todo acesso cai na mesma chave, uma partição fica sobrecarregada (partição quente). Chave boa tem muitos valores diferentes.
Fase 1-3 · Na imagem

Um item, uma partição, três cópias

  • Mais itens, mais partições: o DynamoDB cria e divide partições sozinho.
  • Como no S3 da Aula 10, cada partição é replicada em três zonas.
CONCEITOAula 11

Leitura eventual e leitura forte

Com cópias em três zonas, uma leitura logo depois da gravação pode cair numa cópia ainda não atualizada. No DynamoDB, a leitura padrão é eventualmente consistente (mais barata). Pedindo ConsistentRead=True, a leitura é forte: sempre devolve a última gravação, e custa o dobro.

exemplo
tabela.put_item(Item={"id": 5, "preco": 99})

tabela.get_item(Key={"id": 5})
# eventual: talvez a versão anterior, por instantes

tabela.get_item(Key={"id": 5}, ConsistentRead=True)
# forte: sempre a versão nova, custa 2x
CuidadoNo S3 da Aula 10, a leitura é sempre forte. No DynamoDB, você escolhe a cada leitura.
Fase 1-3 · Diagnóstico

Leitura eventual ou forte?

  • a) A vitrine lista os produtos para quem entra no site.
  • b) Antes de fechar a compra, a loja confere o estoque que acabou de baixar.

a) eventual: um produto que aparece um segundo depois não prejudica ninguém, e a leitura custa metade.

b) forte: ler um estoque antigo pode vender o que não existe.

FASE 2-1 · CONTEÚDO NOVO

Tabela, item e chave

As peças do DynamoDB e a escolha mais importante: a chave.

CONCEITOAula 11

DynamoDB

O banco NoSQL gerenciado e serverless da AWS: não há servidor para criar, nem disco para dimensionar. Você cria a tabela, grava e lê pela API, e paga pelo uso. Responde em poucos milissegundos com qualquer volume.

exemplo
tabela     loja-produtos
item       um produto
atributo   id, nome, preco, tamanho
chave      id (obrigatório em todo item)

aws dynamodb list-tables
Pense assimComo a Lambda é para o código, o DynamoDB é para os dados: você não cuida de máquina nenhuma.
CONCEITOAula 11

Tabela, item e atributo

A tabela guarda itens; cada item é um conjunto de atributos (nome e valor). Só os atributos da chave são obrigatórios: o resto pode variar de item para item.

exemplo
{
  "id":      {"N": "1"},
  "nome":    {"S": "Camiseta básica"},
  "preco":   {"N": "39.90"},
  "tamanho": {"S": "M"}
}

S texto · N número · BOOL · L lista · M mapa
CuidadoNa CLI, cada valor vem com o tipo (S, N). No Python com boto3.resource, o tipo some: você grava um dicionário comum.
CONCEITOAula 11

Chave primária

Identifica cada item de forma única. Pode ser simples, só a chave de partição (ex.: id), ou composta: chave de partição + chave de ordenação, que deixa vários itens com a mesma partição, ordenados.

exemplo
simples     id = 1                        um item por id

composta    pedido_id = 77  +  item = 1
            pedido_id = 77  +  item = 2
            pedido_id = 78  +  item = 1

Query(pedido_id = 77) -> os itens do pedido, em ordem
CuidadoA chave não muda depois de criar a tabela. Errou a chave, é tabela nova e cópia dos dados.
Fase 2-1 · Monte a chave

Qual chave primária para cada tabela?

  • a) Produtos da loja, sempre buscados pelo id.
  • b) Avaliações: a página do produto lista todas as avaliações dele, da mais nova para a mais antiga.
  • c) Sessões de login, buscadas pelo token.

a) partição id, simples.

b) partição produto_id + ordenação data: uma Query traz todas as avaliações do produto, já ordenadas.

c) partição token, simples.

CONCEITOAula 11

boto3

A biblioteca da AWS para Python. Já vem instalada na Lambda. Com boto3.resource("dynamodb").Table(...), cada operação vira um método, e os itens são dicionários Python.

exemplo
import boto3

tabela = boto3.resource("dynamodb").Table("loja-produtos")

tabela.put_item(Item={"id": 4, "nome": "Boné", "preco": 49})
tabela.get_item(Key={"id": 4}).get("Item")
tabela.scan()["Items"]
CuidadoNúmeros voltam como Decimal, não float. O json.dumps não sabe converter Decimal: a função precisa ensinar (Fase 3-2).
CONCEITOAula 11

Query e Scan

Query vai direto à partição da chave pedida: lê só o que interessa. Scan percorre a tabela inteira e cobra por tudo o que leu, mesmo o que for filtrado depois.

Pense assimQuery é ir à gaveta certa do arquivo. Scan é abrir todas as gavetas para achar uma pasta.
exemplo
Query(produto_id = 3)
  lê 12 avaliações -> cobra 12

Scan(FilterExpression: produto_id = 3)
  lê 1.000.000 de avaliações
  devolve 12 -> cobra 1.000.000
CuidadoNa loja de hoje, GET /produtos usa Scan porque o catálogo é pequeno. Com milhares de itens, lista-se por página ou por uma chave.
CONCEITOAula 11

Gravação condicional

PutItem substitui o item se a chave já existir, sem avisar. Com uma ConditionExpression, o banco só grava se a condição valer; se não valer, a gravação é recusada com ConditionalCheckFailedException.

exemplo
tabela.put_item(
    Item=dados,
    ConditionExpression="attribute_not_exists(id)",
)

id novo       -> grava, a API responde 201
id existente  -> recusa, a API responde 409
Pense assimMatrícula: o sistema só cria se ainda não existe aluno com aquele número.
FASE 2-3 · CONTEÚDO NOVO

Permissão e custo

A função precisa de permissão para tocar na tabela, e a conta fecha em centavos se a leitura for pela chave.

CONCEITOAula 11

Papel de execução (IAM role)

Toda Lambda roda com um papel: uma identidade da AWS com uma lista de permissões. A Lambda da Aula 7 recebeu um papel que só escreve logs. Para usar a tabela, o papel precisa de uma política que libere as ações no DynamoDB.

exemplo
{
  "Effect": "Allow",
  "Action": ["dynamodb:GetItem",
             "dynamodb:PutItem",
             "dynamodb:Scan"],
  "Resource": "arn:aws:dynamodb:...:table/loja-produtos"
}
CuidadoMenor privilégio: só as ações usadas, só nesta tabela. dynamodb:* em * funciona, e é exatamente o que um invasor gostaria de achar.
Fase 2-3 · Na imagem

Quem deixa a função ler a tabela

  • A função não tem senha do banco: ela assume o papel, e a AWS confere a política a cada pedido.
  • Sem a política, o erro aparece no log do CloudWatch: AccessDeniedException.
CONCEITOAula 11

Modos de capacidade

Sob demanda (on-demand): paga por pedido, sem configurar nada; ideal para tráfego imprevisível ou pequeno. Provisionado: você reserva leituras e gravações por segundo e paga a reserva, mesmo parada; compensa com tráfego alto e constante.

exemplo
sob demanda (us-east-1)
  gravação  US$ 0,625 por milhão
  leitura   US$ 0,125 por milhão

armazenamento: 25 GB grátis por mês
depois: US$ 0,25 por GB/mês
CuidadoA unidade de leitura cobre até 4 KB com leitura forte, ou 8 KB com leitura eventual. Item maior gasta mais de uma unidade.
Fase 2-3 · Faça a conta

def para_json(valor):
    """O DynamoDB devolve Decimal; o JSON não conhece."""
    if isinstance(valor, Decimal):
        return int(valor) if valor % 1 == 0 else float(valor)
    raise TypeError(type(valor))

def resposta(status, dados):
    return {
        "statusCode": status,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps(dados, ensure_ascii=False, default=para_json),
    }
  • A lista PRODUTOS sai do código. Entra a tabela, criada fora do handler: é aproveitada entre execuções.
  • para_json ensina o json.dumps a converter Decimal: inteiro vira int, o resto vira float.
  • chave_valida continua igual à da Aula 9.

    if rota == "GET /produtos":

        produto_id = int(event["pathParameters"]["id"])
        item = tabela.get_item(Key={"id": produto_id}).get("Item")
        if item is None:
            return resposta(404, {"erro": "produto não encontrado"})

  • scan() traz a tabela toda: serve para o catálogo pequeno.
  • get_item vai direto ao item pela chave. O id chega da URL como texto: int(...) converte, porque a chave é Number.
  • Item que não existe: get devolve None, e a API responde 404.
Fase 3-2 · No editor da Lambda

Cadastrar sem sobrescrever

lambda_function.py (cadastro)
    if rota == "POST /produtos":
        dados = corpo(event)
        if dados.get("preco", 0) <= 0 or not dados.get("nome"):
            return resposta(422, {"erro": "nome e preço positivo"})
        try:
            tabela.put_item(
                Item=dados,
                ConditionExpression="attribute_not_exists(id)",
            )
        except ClientError as erro:
            codigo = erro.response["Error"]["Code"]
            if codigo == "ConditionalCheckFailedException":
                return resposta(409, {"erro": "id já cadastrado"})
            raise
        return resposta(201, dados)
  • corpo(event) lê o JSON com parse_float=Decimal: o boto3 recusa float.
  • Sem nome ou com preço zero: 422.
  • A condição attribute_not_exists(id) impede sobrescrever: id repetido vira 409.
  • O POST /carrinho/total agora busca cada preço no banco. Cole o arquivo inteiro do zip e clique em Deploy.
