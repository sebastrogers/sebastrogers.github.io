CONCEITOAula 9

Gerenciamento de API

O conjunto de controles que ficam na frente da API para decidir quem pode usar, quanto pode usar, qual versão cada um vê e como ela está se comportando.

exemplo
quem?          autenticação e autorização
quanto?        limite de uso (throttling)
qual versão?   estágios e contrato
como está?     métricas e logs

Na AWS, quem faz isso é o API Gateway.
Pense assimA portaria de um prédio: confere quem entra, controla a fila e anota o movimento. Os apartamentos (as funções) nem ficam sabendo.
Fase 1-1 · Caso real

O que acontece com uma API sem limite

CENÁRIO 1

O SMS que virou prejuízo

Uma rede social cobrava por SMS de "esqueci a senha". Um script chamou a rota dezenas de milhares de vezes, e a empresa perdeu milhares de dólares em minutos.

CENÁRIO 2

A conta de US$ 13 que virou US$ 8 mil

Um arquivo cresceu além do que o cache guardava. Sem alerta de custo nem limite de gasto, todos os clientes baixaram direto do armazenamento, e a fatura do mês explodiu.

A LIÇÃO

Limite é requisito

A OWASP lista o consumo ilimitado de recursos entre os 10 riscos mais críticos de APIs (API4:2023). A defesa: limitar quem usa e quanto usa, e ter alerta de custo.

Cenários resumidos de OWASP API Security Top 10 2023, API4:2023 Unrestricted Resource Consumption.

FASE 1-2 · CONTEÚDO NOVO

Quem é você?

Antes de responder, a API precisa saber quem está pedindo e o que essa pessoa pode fazer.

CONCEITOAula 9

Autenticação e autorização

Autenticação responde "quem é você?": o cliente prova a identidade com uma credencial. Autorização responde "o que você pode fazer?": a API decide se aquela identidade tem permissão.

Pense assimNo prédio: o crachá mostra quem você é (autenticação); a catraca só libera o seu andar (autorização).
exemplo
autenticação    quem é você?        chave, senha, token
autorização     o que pode fazer?   papel, permissão, escopo

primeiro autentica, depois autoriza
CuidadoEm inglês: authentication (authn) e authorization (authz). Os nomes parecidos confundem até em documentação.
Fase 1-2 · Fluxograma

O caminho de um pedido pela portaria

  • 401: "não sei quem você é". Faltou a credencial, ou ela é inválida.
  • 403: "sei quem você é, mas você não pode". 429: "pode, mas pediu demais".
CONCEITOAula 9

Chave de API

Um texto único entregue a cada cliente da API e enviado em todo pedido, num cabeçalho como x-api-key. Serve para identificar o programa que chama, e assim limitar e cobrar o uso de cada um.

exemplo
GET /produtos HTTP/1.1
Host: abc123.execute-api.us-east-1.amazonaws.com
x-api-key: loja-turma-2026

sem a chave   -> 401
chave errada  -> 401
chave certa   -> 200
CuidadoA chave identifica um programa, não uma pessoa. Para saber qual usuário está logado, usa-se login e token.
CONCEITOAula 9

Token (JWT)

Depois do login, o servidor entrega um token: um texto assinado dizendo quem é o usuário e até quando vale. O cliente manda o token a cada pedido, e a API confere a assinatura sem consultar banco. O formato mais comum é o JWT (JSON Web Token).

exemplo
Authorization: Bearer eyJhbGciOi...

1. usuário faz login uma vez
2. recebe o token (vale 1 hora, por exemplo)
3. manda o token em todo pedido
4. a API confere a assinatura e o prazo
CuidadoO conteúdo do JWT é só codificado, não criptografado: qualquer um lê. Nunca coloque senha dentro dele.
Fase 1-2 · Na imagem

As três partes de um JWT

Os três pedaços vão juntos, separados por ponto. Se alguém mudar o conteúdo, a assinatura deixa de bater. Especificação: RFC 7519.

Fase 1-2 · Diagnóstico

Qual código a API deve responder?

  • a) O app chama /produtos sem cabeçalho de chave.
  • b) Um cliente logado tenta apagar um produto, mas só gerentes podem.
  • c) Uma chave válida faz 50 pedidos num segundo, e o limite é 10.

a) 401: não há credencial, a API não sabe quem é.

b) 403: a API sabe quem é, mas ele não tem permissão.

c) 429: identidade e permissão em ordem, mas passou do limite.

Fase 1-3 · A decisão de hoje

O que vamos fazer na loja, e o que se faz no mercado

NA AULA · HTTP API

Chave conferida pela função

A loja-api lê o cabeçalho x-api-key e compara com a chave guardada numa variável de ambiente. O limite de uso fica no API Gateway, por estágio.

NO MERCADO

Portaria antes da função

Um autorizador (JWT ou Lambda) barra o pedido antes de chegar à função, ou uma REST API com chaves e planos de uso dá um limite diferente para cada cliente.

O conceito é o mesmo nos três jeitos. Muda só onde a credencial é conferida.

Fase 1-3 · Qual escolher?

Uma loja vai vender acesso à API de catálogo para parceiros, com planos Básico e Premium. HTTP ou REST API?

  • Plano Básico: 1.000 pedidos por dia.
  • Plano Premium: 100.000 pedidos por dia.
  • Cada parceiro com a sua chave.

REST API: chaves de API e planos de uso com cota por cliente só existem nela. A HTTP API limita por estágio e rota, não por cliente.

FASE 2-1 · CONTEÚDO NOVO

Chave e segredo

Onde a chave fica guardada, como ela passa pelo navegador e o que ela não protege.

CONCEITOAula 9

Variável de ambiente

Um valor de configuração guardado fora do código, que a função lê quando roda. Trocar a chave vira mudar uma configuração, sem editar nem publicar o código.

exemplo
import os

CHAVE = os.environ.get("CHAVE_LOJA", "")

# no console: Configuration ›
#   Environment variables › CHAVE_LOJA
CuidadoSegredo não vai no código: código vai para o Git, o Git vai para o GitHub, e o GitHub pode ser público.
CONCEITOAula 9

CORS e o cabeçalho novo

Quando o site manda um cabeçalho fora do padrão, como x-api-key, o navegador primeiro pergunta à API se pode: um pedido OPTIONS, chamado preflight. A API responde com a lista de cabeçalhos aceitos em Access-Control-Allow-Headers. Se x-api-key não estiver na lista, o navegador nem envia o pedido.

exemplo
OPTIONS /produtos
Origin: http://loja-equipe.s3-website...
Access-Control-Request-Headers: x-api-key

resposta da API:
Access-Control-Allow-Headers: content-type, x-api-key

na lista    -> o GET sai com a chave
fora dela   -> erro de CORS no F12
CuidadoO curl não faz essa pergunta: CORS é uma regra do navegador. Por isso o curl funciona e o site, não.
Fase 2-1 · Cuidado

Abra o código-fonte do site. A chave está lá, para quem quiser ver.

Chave dentro de site público não é segredo: ela identifica o site e permite limitar o uso dele, mas não protege dados. Dado sensível exige login do usuário, com token, conferido no servidor.

FASE 2-2 · CONTEÚDO NOVO

Limite de uso

Com chave ou sem chave, ninguém pode chamar a API sem limite.

CONCEITOAula 9

Limite de uso (throttling)

Uma regra que limita quantos pedidos por segundo a API aceita. Passou do limite, o API Gateway responde 429 Too Many Requests sem nem chamar a função. Na AWS, o limite tem dois números: a taxa e a rajada.

exemplo
taxa (rate)     pedidos por segundo, em ritmo constante
rajada (burst)  quantos podem chegar de uma vez

taxa 10 · rajada 20
  20 pedidos juntos: passam
  depois, 10 por segundo
Pense assimO caixa do banco que atende 10 pessoas por minuto e tem 20 cadeiras de espera. A 21ª pessoa não entra.
Fase 2-2 · Na imagem

O algoritmo do balde de fichas

  • O API Gateway usa o algoritmo token bucket: cada pedido gasta uma ficha; a torneira repõe fichas a cada segundo.
  • Balde cheio permite uma rajada; balde vazio devolve 429 até a torneira repor.
Fase 2-2 · E o cliente?

O app recebeu 429. O que ele deve fazer?

resposta
HTTP/2 429
{"message": "Too Many Requests"}

Esperar e tentar de novo, aumentando a espera a cada falha: 1 s, 2 s, 4 s. A técnica se chama backoff exponencial.

Tentar de novo na mesma hora, em loop, só piora: é o próprio cliente gastando as fichas.

FASE 2-3 · CONTEÚDO NOVO

Versões, métricas e custo

Mudar a API sem quebrar quem usa, medir como ela se comporta e quanto o limite economiza.

CONCEITOAula 9

Contrato e versão

O contrato de uma API é o que ela promete: as rotas, os campos que recebe e os campos que devolve. Uma versão é uma foto desse contrato. Mudança que quebra o contrato exige versão nova; a antiga continua no ar por um tempo.

exemplo
compatível (não quebra)       incompatível (quebra)
acrescentar uma rota          remover uma rota
acrescentar um campo          renomear um campo
                              mudar o tipo de um campo
                              tornar obrigatório o que era opcional
Pense assimTrocar o cardápio do restaurante sem avisar quem pede sempre o mesmo prato: o cliente fiel é o primeiro a reclamar.
Fase 2-3 · Na imagem

Dois estágios, a mesma API

  • O estágio v1 fica com a implantação congelada: o Auto-deploy está desligado.
  • O $default recebe cada mudança na hora. Quem usa /v1/... não percebe nada.
RELEMBREAula 7

Logs no CloudWatch

Cada execução da função escreve no CloudWatch Logs: o print, o início, o fim e a linha REPORT com a duração.

exemplo
START RequestId: 5c1e...
pedido: GET /produtos
END RequestId: 5c1e...
REPORT Duration: 2.10 ms  Billed Duration: 3 ms
CONCEITOAula 9

Métrica

Um número medido ao longo do tempo. O log conta a história de um pedido; a métrica mostra o comportamento de todos. O API Gateway manda métricas para o CloudWatch a cada minuto, sem configurar nada.

exemplo
Count     quantos pedidos chegaram
4xx       erros de quem pediu (401, 404, 429...)
5xx       erros do servidor
Latency   quanto tempo a API levou para responder
CuidadoMétricas detalhadas por rota existem, mas precisam ser ligadas e são cobradas à parte.
Fase 2-3 · Diagnóstico

O gráfico de 5xx subiu de repente. Onde procurar?

  • 4xx estável
  • 5xx subindo
  • Count normal

5xx é erro do servidor: a função quebrou. O próximo passo são os logs da `loja-api` no CloudWatch, procurando a linha de erro (Traceback).

Se fosse o 4xx subindo, o problema provável estaria em quem chama: chave errada, rota que não existe, limite estourado.

Fase 3-1 · No editor da Lambda

lambda_function.py: conferir a chave

lambda_function.py
import json
import os

CHAVE = os.environ.get("CHAVE_LOJA", "")
...

def chave_valida(event):
    cabecalhos = event.get("headers") or {}
    return CHAVE != "" and cabecalhos.get("x-api-key") == CHAVE


def lambda_handler(event, context):
    rota = event.get("routeKey")
    print("pedido:", rota)

    if not chave_valida(event):
        return resposta(401, {"erro": "chave ausente ou inválida"})
  • A chave vem da variável de ambiente, não está escrita no código.
  • O API Gateway entrega os nomes de cabeçalho em minúsculas: por isso "x-api-key".
  • Sem a chave certa, a função para ali e responde 401. As rotas da Aula 8 continuam embaixo, iguais.
  • Deploy depois de colar.

Fase 3-2 · No CloudShell

Provocar o 429

carga.sh
API=https://SEU-ID.execute-api.us-east-1.amazonaws.com
for i in $(seq 1 30); do
  curl -s -o /dev/null -w "%{http_code}\n" \
       -H "x-api-key: loja-turma-2026" "$API/produtos"
done | sort | uniq -c
saída
$ bash carga.sh
      6 200
     24 429
# exemplo: os números mudam a cada execução

  • Com taxa 1 e rajada 2, a maioria volta 429.
  • A AWS trata o limite como meta, não como teto exato: os números variam um pouco.
  • Depois do teste, volte para valores de uso normal, como taxa 10 e rajada 20.
