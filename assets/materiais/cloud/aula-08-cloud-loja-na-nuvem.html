RELEMBREAula 1

O que é nuvem

Usar computação de outra empresa pela rede, sob demanda, pagando pelo que usar. O NIST resume em cinco características.

Pense assimEnergia elétrica: ninguém tem usina em casa; liga na tomada e paga a conta do que gastou.
CuidadoServidor alugado por um ano, sem elasticidade e sem medição, não é nuvem: é hospedagem.
exemplo
1. Autoatendimento sob demanda    (você cria sozinho, na hora)
2. Acesso amplo pela rede         (de qualquer lugar)
3. Recursos compartilhados        (vários clientes, mesmo hardware)
4. Elasticidade rápida            (cresce e encolhe)
5. Serviço medido                 (paga pelo uso)
RELEMBREAula 2

Camadas de serviço

Quanto mais alta a camada, menos coisa fica sob sua responsabilidade e mais a AWS cuida por você.

CuidadoResponsabilidade compartilhada: a AWS protege a nuvem; você protege o que coloca nela, como um bucket público por engano.
exemplo
IaaS   EC2         você cuida do sistema operacional para cima
PaaS   Beanstalk   você cuida da aplicação
FaaS   Lambda      você cuida só da função
SaaS   Gmail       você só usa

Hoje: S3 (armazenamento), Lambda (FaaS) e API Gateway (serviço gerenciado)
RELEMBREAula 4

Região e zona de disponibilidade

Região é um lugar do mundo com vários data centers da AWS. Zona de disponibilidade é um desses data centers, isolado dos outros. Cada recurso nasce numa região.

Cuidado"Sumiu minha função!" quase sempre é região errada no canto superior direito do console.
exemplo
us-east-1   N. Virginia (EUA)   mais serviços, preços menores
sa-east-1   São Paulo           menor latência no Brasil, mais caro

Hoje, todos em us-east-1: o recurso que você criar
só aparece na região onde foi criado.

Bucket e objeto

Bucket é um contêiner de arquivos com nome único no mundo. Cada arquivo dentro dele é um objeto, com uma chave (o nome) e o conteúdo.

Pense assimUma gaveta com etiqueta única no mundo inteiro; cada papel dentro dela é um objeto.
CuidadoNome de bucket: só minúsculas, números e hífen, e ninguém no mundo pode ter usado antes.
exemplo
bucket:  loja-roupas-ana-2026
objeto:  index.html
endereço do site:
http://loja-roupas-ana-2026.s3-website-us-east-1.amazonaws.com

A política que libera a leitura

bucket policy
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "LeituraPublica",
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::NOME-DO-BUCKET/*"
  }]
}
  • Principal: "*": qualquer pessoa.
  • s3:GetObject: só ler arquivos, nunca apagar ou enviar.
  • Troque NOME-DO-BUCKET pelo seu. O /* no fim vale para todos os arquivos do bucket.

RELEMBREAula 3

Pagar pelo uso

Na nuvem, o custo vem do uso: quanto se guarda, quantas vezes se acessa e quanto dado sai para a internet. Gasto de capital (comprar servidor) vira gasto operacional (conta mensal).

CuidadoBarato não é grátis: um bucket esquecido com muitos arquivos vira cobrança todo mês.
exemplo
CAPEX   comprar servidor: paga tudo antes, usando ou não
OPEX    nuvem: paga por mês, pelo que usou

S3 Standard (us-east-1), valores de referência:
  armazenamento   US$ 0,023 por GB por mês
  leitura (GET)   US$ 0,0004 por 1.000 pedidos

RELEMBREAula 7

Função como serviço (Lambda)

Você escreve só a função; a AWS cuida do servidor, liga quando chega um evento e desliga depois. Cobra por chamada e pelo tempo de execução.

Pense assimUm caixa que só aparece quando chega cliente, atende e vai embora. Você paga pelos minutos de atendimento.
CuidadoA Lambda não guarda nada entre uma chamada e outra. Dado que precisa durar vai para um banco ou para o S3.
exemplo
evento chega  ->  Lambda acorda  ->  roda lambda_handler(event, context)
                                ->  devolve a resposta  ->  dorme

Sempre grátis: 1 milhão de chamadas por mês
RELEMBREAula 7

JSON

Formato de texto para trocar dados entre programas. Parece um dicionário do Python: chaves entre aspas, valores, listas entre colchetes.

CuidadoJSON usa aspas duplas e true/false minúsculos. Aspas simples quebram o formato.
exemplo
[
  {"id": 1, "nome": "Camiseta básica", "preco": 39.9},
  {"id": 2, "nome": "Calça jeans", "preco": 129.9}
]

json.dumps(dados)   # Python -> texto JSON
json.loads(texto)   # texto JSON -> Python

Fase 2-2 · No editor da Lambda

Parte 2: duas rotas numa função

lambda_function.py (parte 2 de 2)
def lambda_handler(event, context):
    rota = event.get("routeKey")        # ex.: "GET /produtos"
    print("pedido:", rota)              # aparece no CloudWatch

    if rota == "GET /produtos":
        return resposta(200, PRODUTOS)

    if rota == "POST /carrinho/total":
        itens = json.loads(event.get("body") or "[]")
        precos = {p["id"]: p["preco"] for p in PRODUTOS}
        subtotal = sum(precos[i["id"]] * i["quantidade"] for i in itens)
        return resposta(200, {
            "subtotal": round(subtotal, 2),
            "frete": frete(subtotal),
            "total": round(subtotal + frete(subtotal), 2),
        })

    return resposta(404, {"erro": "rota não encontrada"})
  • routeKey é o "método + caminho" que o API Gateway manda: GET /produtos ou POST /carrinho/total.
  • O corpo do POST chega como texto: json.loads transforma em lista de itens.
  • O print vai para os logs do CloudWatch (Fase 2-3). Qualquer outra rota devolve 404.
  • Cole embaixo da parte 1 e clique em Deploy.

RELEMBREAula 7

Início a frio

Na primeira chamada depois de um tempo parada, a AWS precisa preparar o ambiente da função. Essa chamada demora mais. As seguintes reaproveitam o ambiente.

CuidadoPara a maioria dos sites, 100 ms a mais na primeira chamada é imperceptível. Para um jogo em tempo real, pode não ser.
exemplo
REPORT Duration: 2.1 ms  Billed Duration: 3 ms  Memory: 128 MB
       Init Duration: 98.4 ms   <- só na primeira chamada

Na Aula 7 a função já tinha uma URL. Para que um API Gateway?

Uma URL por função vira bagunça quando a loja tem dez funções. A API dá um endereço só, com rotas organizadas, controle de acesso, limite de chamadas, CORS e versões (estágios).

RELEMBREConteúdo novo

API e rota

API é a porta que um programa oferece para outros programas conversarem com ele. Rota é a combinação de método HTTP + caminho, e cada rota leva a uma ação.

Pense assimA recepção de uma loja: um endereço só, e a recepcionista encaminha cada pedido para o setor certo.
exemplo
GET  /produtos         -> lista a vitrine
POST /carrinho/total   -> calcula o total

https://abc123.execute-api.us-east-1.amazonaws.com/produtos
└────────── endereço da API ──────────┘└─ rota ─┘
RELEMBREConteúdo novo

Verbos e códigos HTTP

O verbo diz a intenção do pedido; o código da resposta diz o que aconteceu.

CuidadoOs códigos 4xx são erro de quem pediu; os 5xx, erro de quem respondeu.
exemplo
GET     buscar dados          200  deu certo
POST    enviar dados          404  rota não existe
PUT     atualizar             403  sem permissão
DELETE  apagar                500  erro dentro do servidor
Fase 3-1 · Conceito

O caminho de um pedido

  • O API Gateway transforma o pedido HTTP num evento e chama a Lambda.
  • Por isso o evento de teste da Fase 2-1 tinha routeKey: é exatamente o que chega agora.
  • Usamos o tipo HTTP API: mais simples e mais barato que o REST API, cerca de US$ 1,00 por milhão de chamadas.

CORS

Por segurança, o navegador só deixa uma página ler a resposta de outro endereço se esse endereço autorizar. A autorização vem em cabeçalhos da resposta: é o CORS.

CuidadoCom CORS errado, o curl funciona e o navegador não. O erro aparece no console do navegador (F12), não na AWS.
exemplo
página:  http://loja-roupas-ana-2026.s3-website-us-east-1.amazonaws.com
API:     https://abc123.execute-api.us-east-1.amazonaws.com

endereços diferentes -> o navegador pergunta à API:
"posso?"  ->  Access-Control-Allow-Origin: *

Fase 3-2 · No computador

index.html: a vitrine vem da API

index.html (do <body> para baixo; o <head> é o mesmo da Fase 1-2)
<body>
  <h1>Loja de Roupas</h1>
  <div id="vitrine">Carregando a vitrine...</div>
  <button id="calcular">Total de 3 camisetas e 1 calça</button>
  <p id="total"></p>

  <script>
    const API = "COLE_AQUI_O_ENDERECO_DA_API";   // sem a barra no final

    fetch(API + "/produtos")
      .then((r) => r.json())
      .then((produtos) => {
        document.getElementById("vitrine").innerHTML = produtos
          .map((p) => `<div class="peca">${p.nome} (${p.tamanho}): R$ ${p.preco.toFixed(2)}</div>`)
          .join("");
      });

    document.getElementById("calcular").onclick = () => {
      fetch(API + "/carrinho/total", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify([{ id: 1, quantidade: 3 }, { id: 2, quantidade: 1 }]),
      })
        .then((r) => r.json())
        .then((c) => {
          document.getElementById("total").textContent =
            `Subtotal R$ ${c.subtotal} · frete R$ ${c.frete} · total R$ ${c.total}`;
        });
    };
  </script>
</body>
</html>
  • Troque COLE_AQUI_O_ENDERECO_DA_API pelo seu Invoke URL, sem barra no fim.
  • fetch faz o pedido; .then espera a resposta e monta as peças na tela.
  • O botão faz o POST com 3 camisetas e 1 calça, o mesmo carrinho dos testes.
  • Suba o arquivo no bucket, substituindo o antigo.

Estágio

Uma API pode ter várias versões publicadas ao mesmo tempo, os estágios. É comum ter dev para testar e prod para os clientes. O estágio $default não aparece no endereço.

Pense assimO provador da loja (dev) e a vitrine da rua (prod): você testa a roupa num antes de expor no outro.
CuidadoCom Auto-deploy no estágio dos clientes, uma rota apagada por engano some para todo mundo na hora.
exemplo
https://abc123.execute-api.us-east-1.amazonaws.com/produtos       ($default)
https://abc123.execute-api.us-east-1.amazonaws.com/dev/produtos   (dev)

Auto-deploy ligado: cada mudança na API publica na hora.
