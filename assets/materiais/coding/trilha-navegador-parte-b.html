00 · base

A base: HTML e CSS, só o necessário

HTML e CSS têm muita coisa. Para programar a página, você precisa de três ideias: as tags dizem o que cada pedaço é, o id e a class dão nome aos pedaços, e o CSS encontra esses nomes com seletores.

HTML · dando nome às coisas
<main>
  <h1>Vitrine</h1>

  <input id="busca" type="search">

  <section id="vitrine">
    <article class="produto">...</article>
    <article class="produto">...</article>
  </section>
</main>
CSS · encontrando pelos nomes
h1          { font-size: 2rem; }   /* pela tag  */
#vitrine    { display: grid; }     /* pelo id   */
.produto    { padding: 12px; }     /* pela classe */

#vitrine .produto h3 { margin: 0; }
/* dentro de #vitrine, nos .produto, os h3 */

É aqui que a trilha engata. O seletor que você escreveu no CSS é exatamente o texto que o JavaScript vai receber para achar o elemento:

A mesma escrita, nos dois lugares
/* CSS */            #vitrine { display: grid; }

// JavaScript        document.querySelector("#vitrine")

Ou seja: você já sabe buscar elementos. Só falta a outra metade — o que fazer depois de achar.

O que você quer nomearUsePor quê
um elemento único na páginaid="vitrine"só pode existir um por página
vários elementos do mesmo tipoclass="produto"pode repetir à vontade
o que o pedaço significaheader, nav, main, section, article, footerleitor de tela e buscador entendem
um agrupamento sem significadodivúltimo recurso, só para layout

Pegadinha

O id é único por página. Se você repetir id="produto" em dez cartões, o querySelector("#produto") devolve só o primeiro e ignora os outros nove — sem erro nenhum. Cartão repetido é class, sempre.

Para fixar

Abra o HTML do seu projeto. Qual id tem o elemento que vai receber a listagem? Se não tiver nenhum, dê um agora — você vai precisar dele no passo 02.

01

O DOM: a página como objeto

O arquivo .html é texto. O navegador lê esse texto de cima para baixo e monta, na memória, uma árvore de objetos: o DOM — Document Object Model, Modelo de Objetos do Documento. É essa árvore que aparece na tela, não o arquivo.

O que você escreveu
<main>
  <h1>Vitrine</h1>
  <section id="vitrine">
    <article class="produto">
      <h3>Camiseta</h3>
    </article>
  </section>
</main>
O que o navegador montou
document
  └ main
      ├ h1              "Vitrine"
      └ section#vitrine
          └ article.produto
              └ h3      "Camiseta"

Cada tag virou um nó com propriedades que o JavaScript lê e troca. E a consequência que muda tudo: mudar o objeto muda a tela na hora. Não existe "salvar" nem "recarregar" para a mudança aparecer.

O arquivo no disco continua exatamente como estava. Por isso recarregar a página desfaz tudo o que o seu código fez: o navegador joga a árvore fora e monta outra a partir do HTML original.

Pegadinha

Como a árvore é montada de cima para baixo, um <script> no <head> roda antes de os elementos existirem — e não acha nada. O <script> vai na última linha antes do </body>. (A alternativa é o atributo defer, que adia a execução.)

Para fixar

Abra qualquer página, F12, aba Elements. O que você está vendo ali é o DOM, não o arquivo. Mude um texto por lá e veja a tela mudar; recarregue e veja voltar.

02

Encontrar elementos

JavaScript
const titulo  = document.querySelector("h1");        // o primeiro h1
const vitrine = document.querySelector("#vitrine");  // pelo id
const cards   = document.querySelectorAll(".produto"); // todos

console.log(cards.length);   // quantos achou

querySelector devolve um elemento — o primeiro que casar — ou null se não achar nada. querySelectorAll devolve todos, numa lista que se percorre com forEach.

Percorrendo o resultado
cards.forEach(card => {
  console.log(card.textContent);
});

Essa lista não é um array de verdade: tem length e forEach, mas não tem map nem filter. Quando precisar deles, converta com [...cards].

Pegadinha

O erro mais comum de todos: Cannot read properties of null. Significa que o querySelector devolveu null e você tentou usar. Duas causas, nesta ordem de frequência: o script rodou antes do elemento existir, ou o seletor está escrito errado — faltou o #, faltou o ponto, ou o nome não bate.

Para fixar

No console de uma página sua, digite document.querySelector("#naoexiste"). Veja que ele devolve null sem reclamar. O erro só aparece na linha seguinte, quando você usa o resultado.

03

Alterar a página

JavaScript
titulo.textContent = "Vitrine da Loja";   // troca o texto

card.classList.add("esgotado");           // liga a classe
card.classList.remove("oculto");          // desliga
card.classList.toggle("aberto");          // inverte

card.dataset.id = 42;                     // guarda um dado no elemento

Repare no que não está aí: nenhuma cor, nenhum tamanho. Existe card.style.color = "red", e funciona, mas espalha aparência pelo JavaScript e acaba com a separação entre conteúdo, apresentação e comportamento.

O jeito certo é o CSS continuar dono da aparência e o JavaScript só decidir quando cada regra vale:

CSS · define como é
.produto.esgotado {
  opacity: .5;
  filter: grayscale(1);
}

.oculto { display: none; }
JavaScript · decide quando
if (produto.estoque === 0) {
  card.classList.add("esgotado");
}

Pegadinha

Existe também o innerHTML, que aceita HTML em texto e é muito prático — você vai usá-lo no passo seguinte. Mas nunca monte innerHTML com algo que o usuário digitou: é assim que código estranho entra na sua página. Para texto digitado, use textContent, que trata tudo como texto puro.

Para fixar

Qual a diferença prática entre el.textContent = "<b>oi</b>" e el.innerHTML = "<b>oi</b>"? Teste no console.

04

Criar elementos a partir de dados

JavaScript
const produtos = [
  { nome: "Camiseta", preco: 39.9 },
  { nome: "Calça",    preco: 129.0 }
];

const vitrine = document.querySelector("#vitrine");

function montarCard(p) {
  const art = document.createElement("article");
  art.className = "produto";
  art.innerHTML = `<h3>${p.nome}</h3><p>R$ ${p.preco.toFixed(2)}</p>`;
  return art;
}

function desenhar(lista) {
  vitrine.innerHTML = "";                          // limpa
  lista.forEach(p => vitrine.append(montarCard(p))); // desenha
}

desenhar(produtos);

Três decisões nesse código, e as três valem para sempre:

  1. Dado e tela separados. produtos é o dado; desenhar é a tela. Quando chegar o filtro, você chama desenhar(outraLista) e nada mais muda.
  2. Uma função por cartão. montarCard recebe um objeto e devolve um elemento. Fácil de ler, fácil de mudar.
  3. Limpar antes de desenhar. Sem o innerHTML = "", cada chamada acrescenta em vez de substituir.

Pegadinha

A lista duplicada é o bug clássico deste passo: você filtra, os resultados aparecem embaixo dos antigos, e o total só cresce. É sempre o innerHTML = "" que ficou de fora.

Para fixar

toFixed(2) formata o preço com duas casas. Qual é o equivalente disso no Python?

05

Eventos

Um evento é algo que aconteceu na página: um clique, uma tecla, um formulário enviado. Você não fica esperando por ele. Você deixa uma função guardada e o navegador a chama quando a hora chegar.

JavaScript
const botao = document.querySelector("#filtrar");

botao.addEventListener("click", function () {
  console.log("alguém clicou");
});

// com função de seta, igual:
botao.addEventListener("click", () => console.log("clicou"));

A função que você entrega é a callback (função de retorno). É o uso prático daquilo que a Parte A repete: função é valor, dá para passar como argumento.

Repare no que se inverteu. No Python que você escreveu, o seu código chama as funções: você manda, a linguagem obedece. Aqui é o contrário — você entrega a função ao navegador, e é ele quem chama, quando e se o evento acontecer. Você não sabe quando, nem se vai acontecer.

Esse é o modelo de toda interface gráfica, em qualquer linguagem: o programa não corre do início ao fim: ele carrega, registra o que sabe fazer, e fica parado esperando. Daí em diante só existe reação. Entender isso vale mais do que decorar a lista de eventos.

EventoDispara quandoUse para
clickclique ou toquebotões, cartões, links de ação
inputa cada tecla digitadabusca que filtra enquanto digita
submitenvio do formuláriocadastrar, salvar, entrar
changeseleção mudouselect, checkbox, radio
bluro campo perdeu o focovalidar um campo ao sair dele

A função recebe um objeto com os dados do evento, por convenção chamado e: e.target é o elemento onde aconteceu, e e.target.value é o que foi digitado.

Filtrando enquanto digita
busca.addEventListener("input", (e) => {
  const termo = e.target.value.toLowerCase();
  const achados = produtos.filter(
    p => p.nome.toLowerCase().includes(termo)
  );
  desenhar(achados);
});

Pegadinha

addEventListener("click", buscar()) — com parênteses — executa a função na hora e registra o resultado dela, que normalmente é undefined. O sintoma é o código rodar sozinho ao carregar a página e o clique não fazer nada. Passe o nome sem parênteses.

Para fixar

Para um botão "Cadastrar" dentro de um <form>, por que submit no formulário é melhor do que click no botão?

06

Formulários

JavaScript
const form  = document.querySelector("#form-produto");
const aviso = document.querySelector("#aviso");

form.addEventListener("submit", (e) => {
  e.preventDefault();            // sem isto, a página recarrega

  const nome  = document.querySelector("#nome").value.trim();
  const preco = Number(document.querySelector("#preco").value);

  if (nome === "") {
    aviso.textContent = "Informe o nome do produto.";
    return;
  }
  if (!(preco > 0)) {
    aviso.textContent = "O preço precisa ser maior que zero.";
    return;
  }

  produtos.push({ nome, preco });
  desenhar(produtos);
  form.reset();
  aviso.textContent = "Produto cadastrado.";
});

Quatro coisas acontecendo aí:

  • preventDefault vem primeiro. O comportamento padrão de um formulário é anterior ao JavaScript: o navegador empacota os campos e pede uma página nova. Sem segurar isso, o resto do seu código some junto com a página.
  • .value é sempre texto. Mesmo num input type="number". Number(...) converte; trim() tira os espaços das pontas.
  • A validação sai cedo. Cada return interrompe ali mesmo — o mesmo padrão de guarda que você usa nas rotas do FastAPI.
  • O aviso vai para a página. Um elemento reservado para isso, nunca alert, que trava o navegador e ninguém mais usa.

Repare no truque de !(preco > 0): ele pega de uma vez o campo vazio, o zero, o negativo e o NaN de quem digitou letra. Escrever preco <= 0 deixaria o NaN passar, porque toda comparação com NaN é falsa.

Pegadinha

Validação no navegador é conveniência, não segurança. Qualquer pessoa manda uma requisição direto na sua API sem passar pela tela. A validação que vale é a do servidor — a que você já escreveu em Python. Esta aqui existe só para a pessoa não descobrir o erro depois de esperar a resposta.

Para fixar

Tire o e.preventDefault() do seu formulário e envie. O que acontece com a página, e por que o console.log some do console?

07

Ligar na sua API

Até agora os produtos estavam escritos dentro do app.js: cadastrar some quando a página recarrega. A API que você escreveu resolve isso, e o fetch é a ponte.

Buscando dados
async function carregarProdutos() {
  const resposta = await fetch("/produtos");

  if (!resposta.ok) {              // 404 e 500 chegam por aqui
    console.error("Falhou:", resposta.status);
    return [];
  }
  return await resposta.json();    // o segundo await
}

async function mostrar() {
  const produtos = await carregarProdutos();
  desenhar(produtos);              // a mesma função do passo 04
}

São dois await: o primeiro espera a resposta chegar, o segundo espera o corpo virar objeto JavaScript. E uma regra que pega todo mundo: o fetch só rejeita quando a rede falha. Um 404 ou um 500 chegam como resposta normal — por isso o teste resposta.ok.

Enviando dados
await fetch("/produtos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ nome: "Camiseta", preco: 39.9 })
});

JSON.stringify converte o objeto em texto e o cabeçalho avisa ao FastAPI que aquilo é JSON. É o par exato de resposta.json(), que faz o caminho de volta.

Pegadinha

Esquecer o await do .json() devolve uma promise (promessa), não os dados. O sintoma é sempre o mesmo, e agora você vai reconhecê-lo: produtos.map is not a function.

Para fixar

Se a rota não existe e o fetch não levanta erro, o que acontece com as linhas seguintes do seu código?
