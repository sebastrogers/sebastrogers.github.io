CONCEITO

Persistência

Dado persistente é o que continua existindo depois que o programa termina. A memória (RAM) é rápida, mas volátil: quando o processo acaba, ela é devolvida ao sistema. Para persistir, o dado precisa ir para o disco, em geral por meio de um banco de dados.

exemplo
memória (RAM)              disco (banco)
─────────────              ─────────────
rápida                     mais lenta
some ao reiniciar          sobrevive ao reinício
só o processo enxerga      vários programas leem

CATALOGO = {...}   ->   tabela produto
Pense assimA memória é o rascunho na mesa; o banco é o arquivo de aço da loja. O rascunho é rápido de usar, mas vai para o lixo no fim do dia.
Fase 1-1 · O que precisa ser guardado?

Na loja, o que deve ir para o banco?

  • a) O catálogo de produtos.
  • b) O total do carrinho, já calculado.
  • c) Os pedidos finalizados.
  • d) A promoção da semana.

a) e c): são fatos do negócio que não podem sumir.

b) é derivado: dá para recalcular a partir dos itens. Guardar o total é pedir para ele ficar desatualizado.

d) depende: se a dona muda toda semana sem programador, vai para o banco; se é regra fixa, fica no código.

Banco relacional

O modelo de tabelas que vocês já conhecem, agora visto do lado de quem programa.

CONCEITO

Banco de dados relacional

Organiza os dados em tabelas. Cada linha é um registro; cada coluna, um atributo. A chave primária identifica a linha sem repetição, e a restrição UNIQUE impede valores repetidos numa coluna.

exemplo
CREATE TABLE produto (
  id      INTEGER PRIMARY KEY,
  nome    TEXT NOT NULL UNIQUE,
  preco   REAL NOT NULL,
  tamanho TEXT NOT NULL
);

 id │ nome             │ preco  │ tamanho
  1 │ Camiseta básica  │  39.90 │ M
  2 │ Calça jeans      │ 129.90 │ G
CuidadoO banco também valida: NOT NULL e UNIQUE são uma segunda linha de defesa, além das regras das classes.
CONCEITO

SQLite

Um banco relacional que cabe num arquivo. Não precisa de servidor, instalação nem senha, e já vem com o Python. É o banco mais usado do mundo: está em celulares, navegadores e milhares de aplicativos.

exemplo
loja/
├── api.py
├── loja.db      <- o banco inteiro está aqui
└── loja/

# o mesmo SQL de sempre:
SELECT nome, preco FROM produto WHERE preco < 100;
Pense assimO SQLite é uma planilha guardada num arquivo; um servidor como o MySQL é um cartório com atendente, fila e senha.

FASE 1-3 · CONTEÚDO NOVO

SQL pelo Python

Antes de qualquer biblioteca: o SQL que vocês conhecem, rodando de dentro do programa.

CONCEITO

Conexão, cursor e commit

A conexão abre o banco. O cursor executa os comandos SQL e percorre os resultados. O commit confirma as alterações: sem ele, nada do que foi inserido ou alterado fica gravado.

exemplo
conexao = sqlite3.connect("exemplo.db")
cursor  = conexao.cursor()

cursor.execute("INSERT ...")
conexao.commit()      # agora está no disco

for linha in cursor.execute("SELECT ..."):
    print(linha)      # cada linha é uma tupla
Pense assimEscrever a lápis e passar a caneta: o execute escreve a lápis, o commit passa a caneta.
Fase 1-3 · Exemplo

exemplos/sqlite_puro.py: o SQL de sempre, dentro do Python

exemplos/sqlite_puro.py
import sqlite3

conexao = sqlite3.connect("exemplo.db")
cursor = conexao.cursor()

cursor.execute("""
    CREATE TABLE IF NOT EXISTS produto (
        id      INTEGER PRIMARY KEY AUTOINCREMENT,
        nome    TEXT NOT NULL UNIQUE,
        preco   REAL NOT NULL,
        tamanho TEXT NOT NULL
    )
""")

# o ? protege contra SQL injection: o valor nunca é colado no texto do SQL
cursor.execute("INSERT OR IGNORE INTO produto (nome, preco, tamanho) VALUES (?, ?, ?)",
               ("Camiseta básica", 39.90, "M"))
conexao.commit()

for linha in cursor.execute("SELECT id, nome, preco FROM produto WHERE preco < ?", (100,)):
    print(linha)

conexao.close()
  • connect cria o arquivo se ele não existir.
  • Os ? são parâmetros: o valor vai separado do texto do SQL.
  • Sem commit(), o INSERT se perde quando o programa termina.
  • Cada linha do SELECT chega como tupla: (1, 'Camiseta básica', 39.9).
CONCEITO

SQL injection

Ataque em que um texto digitado pelo usuário vira parte do comando SQL. Acontece quando o programa monta o SQL colando strings. Com parâmetros (?), o banco trata o valor sempre como dado, nunca como comando.

exemplo
nome = "x' OR '1'='1"

# PERIGO: o texto vira SQL
f"SELECT * FROM produto WHERE nome = '{nome}'"
# -> devolve TODOS os produtos

# CERTO: o valor vai separado
cursor.execute("SELECT * FROM produto WHERE nome = ?", (nome,))
CuidadoNunca use f-string para montar SQL com dado vindo de fora. O ORM da Fase 2-2 usa parâmetros automaticamente.
Fase 1-3 · Diagnóstico

O programa roda sem erro, mas o produto não aparece no banco. Por quê?

cadastro.py
conexao = sqlite3.connect("loja.db")

FASE 2-1 · CONTEÚDO NOVO

Camadas

Se a rota fizer tudo (HTTP, regra e SQL), qualquer mudança quebra tudo. A saída é dividir o trabalho.

CONCEITO

Arquitetura em camadas

O código é dividido em camadas, cada uma com uma responsabilidade. Uma camada só conversa com a de baixo, e não sabe como a de baixo faz o trabalho. Mudar uma camada não obriga a mexer nas outras.

exemplo
rota         fala HTTP
  │
serviço      aplica as regras do negócio
  │
repositório  traduz objeto <-> linha
  │
banco        guarda no disco
Pense assimO restaurante: o garçom anota (rota), o chef decide como fazer (serviço), o estoquista busca na despensa (repositório). O cliente nunca entra na despensa.

Teste rápido: se a frase "o serviço sabe que existe um 404" for verdadeira no seu código, a separação vazou.

CONCEITO

Repositório

Uma classe que esconde o banco atrás de métodos com nomes do negócio: adicionar, buscar, listar, atualizar, remover. Quem usa o repositório recebe e entrega objetos do domínio, nunca linhas de tabela.

exemplo
repo = RepositorioProdutos(sessao)

produto_id = repo.adicionar(camiseta)
produto    = repo.buscar(produto_id)   # um Camiseta
repo.listar(tamanho="M")
repo.remover(produto_id)
Pense assimO estoquista: você pede "a camiseta 7" e recebe a camiseta. Em qual prateleira ela estava não é problema seu.
CONCEITO

Serviço

A camada das regras de negócio que envolvem mais de um objeto ou consultam o que já existe. Ele usa o repositório e, quando algo dá errado, levanta uma exceção com nome do negócio.

exemplo
servico = ServicoCatalogo(repo)

servico.cadastrar(dados)
# nome já existe?  -> ProdutoJaExiste
# preço zero?       -> DadosInvalidos
# tudo certo        -> devolve com id
CuidadoRegra que vale para um único objeto (preço positivo) fica na classe do domínio. Regra que precisa olhar o banco (nome único) fica no serviço.
FASE 2-2 · CONTEÚDO NOVO

ORM e SQLModel

Escrever SQL à mão para cada consulta cansa e erra. Um ORM faz a tradução entre classes e tabelas.

CONCEITO

ORM (mapeamento objeto-relacional)

Uma biblioteca que traduz entre o mundo dos objetos e o mundo das tabelas. A classe vira tabela, o objeto vira linha, o atributo vira coluna, e o SQL é gerado pelo ORM, sempre com parâmetros.

exemplo
Python                  banco
──────                  ─────
classe ProdutoRegistro  tabela produto
objeto                  linha
atributo preco          coluna preco
sessao.add(obj)         INSERT INTO ...
sessao.get(Cls, 1)      SELECT ... WHERE id = ?
Pense assimUm intérprete numa reunião: cada um fala a própria língua, e o intérprete traduz nos dois sentidos.
CONCEITO

SQLModel

O ORM do mesmo autor do FastAPI. Uma classe com table=True vira tabela; Field define chave primária e restrições. Por baixo, ele usa o SQLAlchemy, o ORM mais usado do Python.

exemplo
class ProdutoRegistro(SQLModel, table=True):
    id: int | None = Field(default=None,
                           primary_key=True)
    nome: str = Field(unique=True)
    preco: float
    tamanho: str
CuidadoO tipo int | None no id é porque, antes de gravar, o produto ainda não tem id: quem gera é o banco.
CONCEITO

Sessão

A conversa com o banco. Você acumula mudanças com add e delete, e o commit grava tudo de uma vez. get busca pela chave primária; exec(select(...)) faz consultas com filtro.

exemplo
with Session(engine) as sessao:
    sessao.add(registro)
    sessao.commit()          # grava
    sessao.refresh(registro) # pega o id gerado

    sessao.get(ProdutoRegistro, 1)
    sessao.exec(select(ProdutoRegistro)
        .where(ProdutoRegistro.preco <= 100))

FASE 2-3 · CONTEÚDO NOVO

Erros e status

O serviço fala a língua do negócio. A rota traduz para a língua do HTTP.

CONCEITO

Exceção do domínio

Uma classe de exceção com nome do negócio, levantada pelo serviço quando uma regra não é cumprida. Quem decide qual código HTTP ela vira é a camada de cima, num único lugar.

exemplo
class ProdutoNaoEncontrado(Exception): ...
class ProdutoJaExiste(Exception): ...
class DadosInvalidos(Exception): ...

raise ProdutoJaExiste("já existe um produto chamado Boné")
Pense assimO chef diz "acabou o salmão". É o garçom que traduz isso para o cliente, do jeito da casa.

CONCEITO

Injeção de dependência (Depends)

Em vez de a rota criar a sessão e o serviço, ela declara que precisa deles, e o FastAPI entrega pronto a cada pedido. Nos testes, dá para trocar a dependência por um banco em memória.

exemplo
def obter_servico(sessao = Depends(obter_sessao)):
    return ServicoCatalogo(RepositorioProdutos(sessao))

@app.get("/produtos/{produto_id}")
def buscar(produto_id: int,
           servico = Depends(obter_servico)):
    return servico.buscar(produto_id)
CuidadoUma sessão por pedido HTTP: abre no começo, fecha no fim. Nunca uma sessão global para o servidor inteiro.
Fase 2-3 · Diagnóstico

Qual código a API deve responder?

  • a) PUT /produtos/7, e não existe produto 7.
  • b) POST /produtos com o nome de um produto que já existe.
  • c) POST /produtos com tamanho "XL".
  • d) DELETE /produtos/2, que existe.

a) 404: o recurso não existe.

b) 409: conflito com o que já está gravado.

c) 422: o formato está certo, mas a regra do domínio recusa.

d) 204: removido, nada para devolver.

from sqlalchemy.pool import StaticPool
from sqlmodel import Field, SQLModel, create_engine

URL_BANCO = "sqlite:///loja.db"


class ProdutoRegistro(SQLModel, table=True):
    """Uma linha da tabela produto: o produto do jeito que o banco guarda."""
    __tablename__ = "produto"

    id: int | None = Field(default=None, primary_key=True)
    tipo: str
    nome: str = Field(unique=True)
    preco: float
    tamanho: str
    manga: str | None = None
    modelagem: str | None = None
  • Uma tabela só, com uma coluna tipo para Produto, Camiseta e Calca.
  • primary_key é o id que o banco gera; unique impede dois produtos com o mesmo nome.
  • A URL do banco fica em um lugar só.

loja/banco.py: a conexão

def criar_engine(url=URL_BANCO):
    # check_same_thread é um argumento só do SQLite: outros bancos não o conhecem
    argumentos = {"check_same_thread": False} if url.startswith("sqlite") else {}
    return create_engine(url, connect_args=argumentos)


def engine_em_memoria():
    """Banco que vive só na memória: ideal para testes rápidos."""
    return create_engine("sqlite://", connect_args={"check_same_thread": False},
                         poolclass=StaticPool)


def criar_tabelas(engine):
    SQLModel.metadata.create_all(engine)
  • criar_engine só passa check_same_thread ao SQLite: outros bancos não conhecem esse argumento.
  • engine_em_memoria cria um banco que só existe enquanto o teste roda.
  • create_all cria as tabelas que ainda não existem, e não apaga dados.

loja/repositorio.py: traduzir nos dois sentidos

loja/repositorio.py
from sqlmodel import Session, select

from loja.banco import ProdutoRegistro
from loja.produto import Calca, Camiseta, Produto

CAMPOS = ("tipo", "nome", "preco", "tamanho", "manga", "modelagem")


def para_dominio(registro):
    """Linha do banco -> objeto do domínio (com as validações de sempre)."""
    if registro.tipo == "Camiseta":
        return Camiseta(registro.nome, registro.preco, registro.tamanho, registro.manga)
    if registro.tipo == "Calca":
        return Calca(registro.nome, registro.preco, registro.tamanho, registro.modelagem)
    return Produto(registro.nome, registro.preco, registro.tamanho)


def para_registro(produto):
    """Objeto do domínio -> linha do banco."""
    return ProdutoRegistro(**produto.para_dict())
  • para_dominio reconstrói o objeto certo pela coluna tipo, e as validações do construtor rodam de novo.
  • para_registro reaproveita o para_dict da Aula 9.

class RepositorioProdutos:
    """Única parte do sistema que sabe que existe um banco."""

    def __init__(self, sessao: Session):
        self.sessao = sessao

    def adicionar(self, produto):
        registro = para_registro(produto)
        self.sessao.add(registro)
        self.sessao.commit()
        self.sessao.refresh(registro)
        return registro.id

    def buscar(self, produto_id):
        registro = self.sessao.get(ProdutoRegistro, produto_id)
        return None if registro is None else para_dominio(registro)
  • commit grava; refresh traz de volta o id que o banco gerou.
  • get busca pela chave primária e devolve None se não achar.

def criar_produto(dados):
    """Dicionário -> objeto do domínio. Erros de validação viram DadosInvalidos."""
    try:
        tipo = dados.get("tipo", "Produto")
        if tipo == "Camiseta":
            return Camiseta(dados["nome"], dados["preco"], dados["tamanho"], dados.get("manga"))
        if tipo == "Calca":
            if not dados.get("modelagem"):
                raise ValueError("calça precisa de modelagem")
            return Calca(dados["nome"], dados["preco"], dados["tamanho"], dados["modelagem"])
        if tipo == "Produto":
            return Produto(dados["nome"], dados["preco"], dados["tamanho"])
        raise ValueError(f"tipo inválido: {tipo}")
    except (ValueError, KeyError) as erro:
        raise DadosInvalidos(str(erro)) from erro
  • O ValueError das classes do domínio vira DadosInvalidos.
  • from erro guarda a causa original, para quem for depurar.
  • Tipo desconhecido ("Sapato") também é dado inválido.

loja/servico.py: o ServicoCatalogo

loja/servico.py (continuação)
def com_id(produto_id, produto):
    return {"id": produto_id, **produto.para_dict()}


class ServicoCatalogo:
    """Recebe o repositório pronto: não sabe se o banco é SQLite, MySQL ou memória."""

    def __init__(self, repositorio):
        self.repositorio = repositorio

    def listar(self, tamanho=None, preco_max=None):
        return [com_id(i, p) for i, p in self.repositorio.listar(tamanho, preco_max)]

    def produto(self, produto_id):
        produto = self.repositorio.buscar(produto_id)
        if produto is None:
            raise ProdutoNaoEncontrado(f"produto {produto_id} não encontrado")
        return produto

    def buscar(self, produto_id):
        return com_id(produto_id, self.produto(produto_id))

    def cadastrar(self, dados):
        produto = criar_produto(dados)
        if self.repositorio.existe_nome(produto.nome):
            raise ProdutoJaExiste(f"já existe um produto chamado {produto.nome}")
        return com_id(self.repositorio.adicionar(produto), produto)
  • O serviço recebe o repositório pronto: não sabe se o banco é SQLite, MySQL ou memória.
  • Nome único é regra do serviço porque precisa consultar o que já está gravado.
  • com_id junta o id ao dicionário do produto: é o que a API devolve.
  • Nenhum 404 aqui: o serviço não sabe que existe HTTP.

def obter_sessao():
    with Session(engine) as sessao:
        yield sessao


def obter_servico(sessao: Session = Depends(obter_sessao)):

@app.exception_handler(ProdutoNaoEncontrado)
def nao_encontrado(request, erro):
    return JSONResponse(status_code=404, content={"detail": str(erro)})


@app.exception_handler(ProdutoJaExiste)
def ja_existe(request, erro):
    return JSONResponse(status_code=409, content={"detail": str(erro)})


@app.exception_handler(DadosInvalidos)
def dados_invalidos(request, erro):

  • yield entrega a sessão para a rota e fecha quando o pedido termina.
