Repositório é a pasta do projeto com memória: o Git guarda cada versão salva. Commit é uma dessas versões, uma foto do projeto com uma mensagem dizendo o que mudou.

Variável e tipo

Variável é um nome que aponta para um valor. Todo valor tem um tipo, que diz o que dá para fazer com ele.

Cuidado"3" é texto, não número: "3" * 2 dá "33".
exemplo
nome = "Camiseta básica"   # str: texto
quantidade = 3             # int: inteiro
preco = 39.90              # float: com casas decimais
em_estoque = True          # bool: verdadeiro ou falso

print(type(preco))         # <class 'float'>
RELEMBREAula 3

Lista e tupla

As duas guardam vários valores em ordem, acessados pela posição, que começa em 0. A lista pode mudar; a tupla, não.

Pense assimA lista é o carrinho: entra e sai peça. A tupla é a tabela de tamanhos: fixa.
CuidadoTAMANHOS.append("GG") dá erro: tupla não muda.
exemplo
carrinho = ["camiseta", "calça"]   # lista: colchetes
carrinho.append("moletom")         # cresce

TAMANHOS = ("P", "M", "G")         # tupla: parênteses

print(carrinho[0])                 # camiseta
print(TAMANHOS[-1])                # G, o último
RELEMBREAula 3

Dicionário

Guarda pares chave e valor. Em vez de achar pela posição, você acha pelo nome da chave.

Pense assimA etiqueta da peça: em "preço" está 159,90; em "tamanho" está P.
CuidadoChave que não existe dá KeyError: produto["cor"].
exemplo
produto = {"nome": "Moletom", "preco": 159.90}

print(produto["preco"])     # 159.9
produto["tamanho"] = "P"    # chave nova
print(len(produto))         # 3

Testes de verdade

O chefe do primeiro mundo. Vamos com calma: o que é um teste, o que o pytest faz, como ler quando dá errado e como escrever o teste antes do código.

Fase 1-3 · Para começar

Numa loja de roupa, ninguém vende a peça sem passar no provador.

Teste é o provador do código. Um programa pequeno que usa o seu programa e confere se a resposta está certa, sozinho, em milissegundos, quantas vezes você quiser.

RELEMBREAula 4

Função

Um bloco com nome, que recebe valores (parâmetros) e devolve um resultado com return. Escreve uma vez, usa quantas vezes quiser.

Pense assimUma máquina: entra matéria-prima, sai produto. Quem usa não precisa saber como ela funciona por dentro.
Cuidadoprint só mostra na tela. return devolve para quem chamou. Só o que é devolvido pode ser testado.
exemplo
def preco_com_desconto(preco, pct):     # parâmetros
    return preco * (100 - pct) / 100    # devolve

valor = preco_com_desconto(100, 10)     # chamada
print(valor)                            # 90.0
RELEMBREAula 4

Módulo e pacote

Módulo é um arquivo .py. Pacote é uma pasta de módulos com um __init__.py. O import traz para o seu arquivo o que está em outro.

CuidadoO import usa o caminho com pontos (loja.calculos), sem o .py.
exemplo
# loja/calculos.py: módulo calculos, no pacote loja

from loja.calculos import total_carrinho
total_carrinho([(10, 2)])            # 20

import loja.calculos
loja.calculos.total_carrinho([])     # 0

"""Etapa 3: funções puras, fáceis de testar (Aula 4)."""

FRETE_FIXO = 15.0
FRETE_GRATIS_A_PARTIR_DE = 200.0


def total_carrinho(itens):
    """Recebe uma lista de (preço, quantidade) e devolve o total."""
    total = 0
    for preco, quantidade in itens:
        total = total + preco * quantidade
    return total
  • Crie a pasta loja/ com um __init__.py vazio: ela vira um pacote que dá para importar.
  • A função recebe a lista e devolve o total, sem print. O que é devolvido pode ser conferido.
  • Função que só recebe e devolve, sem tela e sem arquivo, é a mais fácil de testar.
Fase 1-3 · Por baixo do pytest

Um teste, sem pytest nenhum

no terminal: python
from loja.calculos import total_carrinho

assert total_carrinho([]) == 0          # verdadeiro: nada acontece
assert total_carrinho([(10, 2)]) == 20  # verdadeiro: nada acontece
assert total_carrinho([(10, 2)]) == 99  # falso: AssertionError
  • assert condição não faz nada se a condição é verdadeira, e explode se é falsa.
  • Todo teste é isso: rodar o código e afirmar o que deveria sair.
  • O pytest só organiza: acha os asserts, roda todos e mostra o placar.

Condição: if e else

Escolhe um caminho conforme uma comparação dê verdadeiro ou falso.

Cuidado> e >= só dão resultados diferentes exatamente na fronteira, em 200. É lá que o teste precisa olhar.
exemplo
valor = 200

if valor >= 200:
    frete = 0
else:
    frete = 15

print(frete)   # 0

"""Etapa 4: o produto vira classe (Aula 6)."""

TAMANHOS = ("PP", "P", "M", "G", "GG")


class Produto:
    def __init__(self, nome, preco, tamanho):
        if not nome or not nome.strip():
            raise ValueError("nome do produto não pode ser vazio")
        if preco <= 0:
            raise ValueError("preço deve ser maior que zero")
        if tamanho not in TAMANHOS:
            raise ValueError(f"tamanho inválido: {tamanho}")
        self.nome = nome.strip()
        self.preco = preco
        self.tamanho = tamanho

    def descricao(self):
        return f"{self.nome} {self.tamanho}: R$ {self.preco:.2f}"
  • Três regras, conferidas antes de guardar qualquer atributo.
  • raise ValueError interrompe a criação com uma mensagem que explica o problema.
  • descricao() é comportamento junto do dado: o produto sabe se apresentar.

class Carrinho:
    def __init__(self):
        self._itens = []   # pares (produto, quantidade)
        self._finalizado = False

    def adicionar(self, produto, quantidade=1):
        if self._finalizado:
            raise CarrinhoFinalizadoError("carrinho finalizado não recebe peças")
        if not isinstance(produto, Produto):
            raise TypeError("só é possível adicionar um Produto")
        if quantidade <= 0:
            raise ValueError("quantidade deve ser positiva")
        self._itens.append((produto, quantidade))
  • self._itens guarda pares (produto, quantidade). O underscore avisa: não mexa direto.

super()

Chama a versão da classe mãe de dentro da filha. No __init__, garante que a parte herdada nasça com as regras da mãe.

class SemPromocao:
    def aplicar(self, subtotal):
        return subtotal


class Percentual:
    def __init__(self, pct):
        if not 0 <= pct <= 100:
            raise ValueError("percentual deve estar entre 0 e 100")
        self.pct = pct

    def aplicar(self, subtotal):
        return subtotal * (100 - self.pct) / 100


class Cupom:
    def __init__(self, valor):
        if valor < 0:
            raise ValueError("valor do cupom não pode ser negativo")
        self.valor = valor

    def aplicar(self, subtotal):
        return max(subtotal - self.valor, 0)   # nunca negativo
  • As três têm aplicar(subtotal): recebe o subtotal, devolve o valor com desconto.
  • Nenhuma herda da outra. O que as une é o nome do método: duck typing.
  • Cada uma protege a própria regra: percentual entre 0 e 100, cupom nunca negativo.

RELEMBREAula 8

Classe abstrata

Uma classe que só define o contrato e não vira objeto. Toda filha é obrigada a implementar os métodos marcados como abstratos.

Pense assimO modelo de contrato da loja: ninguém assina o modelo em branco, mas todo contrato real precisa ter as cláusulas dele.
CuidadoO contrato confere o nome do método, não se a conta está certa. Isso é papel do teste.
exemplo
from abc import ABC, abstractmethod

class Promocao(ABC):
    @abstractmethod
    def aplicar(self, subtotal): ...

Promocao()   # TypeError: não vira objeto
RELEMBREAulas 6, 7 e 8

Decorador

A linha com @ em cima de uma função muda o comportamento dela, sem mexer no corpo. Na loja, já usamos três.

exemplo
@property                  # lê como atributo
@abstractmethod            # obriga a filha a implementar
@pytest.mark.parametrize   # roda o teste várias vezes

"""Etapas 7 e 8: promoções com contrato (Aula 8)."""
from abc import ABC, abstractmethod


class Promocao(ABC):
    """Contrato: aplicar devolve o valor com desconto."""

    @abstractmethod
    def aplicar(self, subtotal):
        ...


class SemPromocao(Promocao):
    def aplicar(self, subtotal):
        return subtotal


class Percentual(Promocao):
    def __init__(self, pct):
        if not 0 <= pct <= 100:
            raise ValueError("percentual deve estar entre 0 e 100")
  • Promocao(ABC) é uma classe abstrata: existe para definir o contrato, não para virar objeto.
  • @abstractmethod marca o obrigatório. Subclasse sem aplicar não nasce.
  • Percentual e Cupom ganham o mesmo (Promocao). O resto não muda.
