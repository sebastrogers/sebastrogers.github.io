CONCEITOAula 9

Cliente e servidor

O cliente é o programa que pede. O servidor é o programa que fica esperando pedidos e responde. Cliente e servidor são papéis, não tipos de máquina.

Pense assimO balcão de uma loja: o cliente não entra no estoque. Faz o pedido no balcão, do jeito combinado, e recebe a resposta.
exemplo
cliente               servidor
(navegador, app,      (programa que espera
 script)               pedidos)

  ─── pedido ──────────────▶
  ◀──────────── resposta ───

O servidor não sabe quem pede.
Só exige que o pedido siga as regras.
CuidadoO mesmo programa pode ser servidor numa conversa e cliente em outra.
Fase 1-1 · Conceito

Quem pode ser cliente

  • Os três primeiros são clientes diferentes falando com o mesmo servidor.
  • Por isso o servidor responde com dados (não com telas): cada cliente mostra do seu jeito.
  • É isso que vamos construir hoje: a loja respondendo com dados para qualquer cliente.

Protocolo

Conjunto de regras de conversa entre programas: o formato de cada mensagem e a ordem delas. O protocolo da web é o HTTP.

Pense assimUm formulário dos Correios: qualquer pessoa preenche, e o carteiro entende porque o formato é sempre o mesmo.
exemplo
HTTP  aplicação   o que se pede     ◀ hoje
                  e o que se responde
TCP   transporte  a entrega chega
                  inteira e em ordem
IP    rede        o endereço de cada
                  computador

Cada camada usa a de baixo
sem saber como ela funciona.
CuidadoO HTTP não guarda memória: o servidor não lembra do pedido anterior. Guarde essa ideia.
Fase 1-1 · Na imagem

Onde o HTTP fica na web

  • HTML, CSS e JavaScript: o que o navegador mostra e executa.
  • HTTP: o pedido e a resposta. É a camada de hoje.
  • TCP e IP: levam os pedaços de um computador ao outro. O HTTP usa sem precisar saber como.
  • TLS: a criptografia. HTTP com TLS é o HTTPS.

FASE 1-2 · CONTEÚDO NOVO

A mensagem HTTP

O endereço, o verbo, os cabeçalhos, o corpo e o código que diz o que aconteceu.

Fase 1-2 · Conceito

A anatomia de um endereço (URL)

http://esquema127.0.0.1host: qual computador:8000porta: qual programa/produtos/3caminho: qual recurso?tamanho=Mconsulta: filtros
  • 127.0.0.1 é o seu próprio computador. Também aparece como localhost.
  • A porta separa os programas de um mesmo computador. A nossa API vai usar a 8000.
  • Na internet seria, por exemplo, https://api.loja.com/produtos/3: o esquema https é o HTTP com criptografia.
Fase 1-2 · Conceito

Pedido e resposta: duas mensagens de texto

pedido (o cliente envia)
GET /produtos/1 HTTP/1.1
Host: 127.0.0.1:8000
Accept: application/json

(sem corpo: GET só busca)
resposta (o servidor devolve)
HTTP/1.1 200 OK
content-type: application/json
content-length: 95

{"id": 1, "tipo": "Camiseta",
 "nome": "Camiseta básica",
 "preco": 39.9, "tamanho": "M",
 "manga": "curta"}
  • Primeira linha: no pedido, método + caminho; na resposta, o código de status.
  • Cabeçalhos: informações sobre a mensagem, como o formato do corpo (content-type).
  • Linha em branco, e depois o corpo: os dados em si.

CONCEITOAula 9

Métodos HTTP

O método (ou verbo) diz a intenção do pedido. O caminho diz em que recurso; o método diz o que fazer com ele.

Pense assimNa loja física: olhar a vitrine (GET), pôr uma peça na sacola (POST), devolver a peça (DELETE).
exemplo
Método  Intenção          Seguro  Idemp.
GET     buscar            sim     sim
POST    criar/processar   não     não
PUT     substituir        não     sim
PATCH   alterar parte     não     não*
DELETE  remover           não     sim

Idemp. = idempotente  * não garantido
CuidadoSeguro = não altera nada no servidor. Usar GET para apagar alguma coisa quebra essa promessa.
CONCEITOAula 9

Idempotência

Uma operação é idempotente quando repetir o pedido deixa o servidor no mesmo estado que fazer uma vez só. Importa porque, na rede, pedidos se repetem: o usuário clica duas vezes, a conexão cai e o app tenta de novo.

Pense assimO botão do elevador: apertar cinco vezes não chama cinco elevadores.
exemplo
DELETE /carrinho
  1 vez:    carrinho vazio
  2 vezes:  carrinho vazio   ✔ idempotente

POST /carrinho/itens
  1 vez:    1 camiseta no carrinho
  2 vezes:  2 camisetas      ✘ não é
CuidadoPor isso o navegador avisa "reenviar formulário?" quando você recarrega depois de um POST.
Fase 1-2 · Conceito

Códigos de status: aprenda as famílias, não a lista

FamíliaQuer dizerOs que aparecem hoje
1xxinformação, a conversa continua(raro no dia a dia)
2xxdeu certo200 OK · 201 Created · 204 No Content
3xxo recurso está em outro lugar301 mudou de endereço · 304 use a cópia que você já tem
4xxerro de quem pediu400 pedido malformado · 404 Not Found · 422 dados inválidos
5xxerro de quem respondeu500 Internal Server Error: o código do servidor quebrou
Regra de bolso4xx: o cliente precisa mudar o pedido. 5xx: o servidor precisa ser consertado. Um 500 na sua API quase sempre é uma exceção que ninguém tratou.
Fase 1-2 · Diagnóstico

O que aconteceu, e de quem é a culpa?

três respostas
GET  /produtos/1     ->  200
GET  /produtos/99    ->  404
POST /carrinho/itens  {"produto_id": 1, "quantidade": 0}  ->  422

200: deu certo, o produto veio no corpo.

404: o recurso 99 não existe. Culpa de quem pediu.

422: o formato chegou certo, mas o conteúdo não passa na validação (quantidade zero). Também é o cliente que precisa corrigir.

JSON: o idioma dos dados

Cliente e servidor podem ser escritos em linguagens diferentes. Eles precisam de um formato de texto que os dois entendam.

RELEMBREAula 3

Dicionário

Coleção de pares chave e valor. Você acessa o valor pela chave, não por posição.

exemplo
produto = {"nome": "Moletom",
           "preco": 159.90,
           "tamanho": "P"}

produto["preco"]          # 159.9
produto["tamanho"] = "M"  # troca
"nome" in produto         # True
Pense assimUma ficha de cadastro: cada campo tem um rótulo e um valor.
CONCEITOAula 9

JSON

JavaScript Object Notation: um formato de texto para trocar dados entre programas, de qualquer linguagem. Parece um dicionário do Python, mas é só texto.

Pense assimUma língua franca: o servidor em Python e o app em JavaScript ou Java falam JSON entre si.
exemplo
Python            JSON
dict  {...}       objeto  {...}
list  [...]       array   [...]
str   "texto"     string  "texto"
int, float        number
True / False      true / false
None              null
CuidadoEm JSON, texto só com aspas duplas. Aspas simples, vírgula sobrando no fim e True com maiúscula não são JSON válido.
Fase 1-3 · No terminal do Python

Do dicionário ao texto, e de volta

python
>>> import json
>>> json.dumps({"nome": "Moletom", "preco": 159.9, "ativo": True, "desconto": None})
'{"nome": "Moletom", "preco": 159.9, "ativo": true, "desconto": null}'

>>> json.loads('{"tamanhos": ["P", "M"], "estoque": 12}')
{'tamanhos': ['P', 'M'], 'estoque': 12}
  • dumps (dump string): Python vira texto JSON. Repare true e null.
  • loads (load string): texto JSON vira Python de novo.
  • Na API, o FastAPI faz isso sozinho: a função devolve um dicionário e ele vira JSON na resposta.
  • O cabeçalho content-type: application/json avisa o cliente de que o corpo é JSON.

class Produto:
    ...  # __init__ e descricao, como na Aula 8

    def para_dict(self):
        """O produto em formato de dicionário, pronto para virar JSON."""
        return {
            "tipo": type(self).__name__,
            "nome": self.nome,
            "preco": self.preco,
            "tamanho": self.tamanho,
        }
  • Um método novo, para_dict, no fim da classe Produto.
  • type(self).__name__ é o nome da classe do objeto: "Produto", "Camiseta" ou "Calca".
  • Por que não converter o objeto direto? O JSON não sabe o que é um objeto Python. Ele só entende dicionários, listas e valores simples.

super() e sobrescrita

A classe filha pode reescrever um método da mãe e, dentro dele, chamar a versão da mãe com super() para reaproveitar o que já existe.

exemplo
class Camiseta(Produto):
    def descricao(self):
        base = super().descricao()
        return f"{base} · manga {self.manga}"

FASE 2-1 · CONTEÚDO NOVO

REST: um jeito de organizar a conversa

O HTTP diz como mandar mensagens. O REST diz como organizar os endereços e os verbos para a API fazer sentido.

CONCEITOAula 9

API

Application Programming Interface: a porta que um programa oferece para outros programas usarem o que ele faz, sem precisar conhecer o código por dentro. A API é um contrato: peça assim e receba assim.

Pense assimO garçom e o cardápio: você pede pelo cardápio, sem entrar na cozinha. A cozinha pode mudar a receita sem mudar o cardápio.
exemplo
o cliente só conhece o contrato:

  GET /produtos
    -> lista de produtos em JSON
  POST /carrinho/itens
    -> 201 e o item adicionado

o que há por dentro (classes, regras,
banco) fica escondido atrás da porta.
CuidadoÉ a mesma ideia de encapsulamento da Aula 6, só que agora entre programas diferentes.
CONCEITOAula 9

REST

Representational State Transfer: um estilo de arquitetura descrito por Roy Fielding em 2000, na tese de doutorado dele. Fielding também foi um dos autores da especificação do HTTP. REST não é biblioteca nem protocolo: é um conjunto de restrições para usar bem o HTTP.

exemplo
API REST, na prática:

• cada coisa tem um endereço
      /produtos/3
• o verbo diz a intenção
      GET, POST, DELETE
• a resposta é uma representação
      JSON
• cada pedido chega completo
      sem memória entre pedidos
Pense assimComo a gramática de uma língua: o HTTP são as palavras, o REST é a forma de montar frases que todo mundo entende.

CONCEITOAula 9

Recurso e representação

Recurso é qualquer coisa que tenha nome no seu domínio: um produto, a lista de produtos, o carrinho. Representação é o formato em que o recurso viaja: hoje, JSON. O endereço identifica o recurso; o método diz o que fazer com ele.

exemplo
um produto
  /produtos/3
  {"id": 3, "nome": "Moletom", ...}

a vitrine
  /produtos
  [ {...}, {...}, {...} ]

o total do carrinho
  /carrinho/total
  {"pecas": 4, "total": 224.64}
CuidadoO recurso é a coisa; o JSON é só uma fotografia dela naquele momento.

Fase 2-1 · Corrija os endereços

O que está errado em cada um?

endereços de uma API mal desenhada

GET  /produto/deletar?id=3

GET /produtos: o verbo "pegar" já é o GET.

POST /carrinho/itens: o POST já diz "adicionar".

GET /produtos?tamanho=M: filtro vai na consulta, não no nome.

FastAPI: o servidor da loja

Escrever um servidor HTTP do zero daria muito trabalho. Um framework faz a parte repetitiva.

CONCEITOAula 9

Framework

Uma biblioteca é chamada pelo seu código. Um framework chama o seu código: ele cuida do fluxo e você escreve só o que é seu. O FastAPI é um framework Python para criar APIs.

exemplo
biblioteca:
  seu código ──chama──▶ json.dumps(...)

framework:
  pedido HTTP ──▶ FastAPI acha a rota
  FastAPI ──chama──▶ sua função
  retorno ──▶ resposta JSON
Pense assimBiblioteca é uma caixa de ferramentas; framework é uma linha de montagem onde você cuida de uma estação.
Fase 2-2 · Conceito

O caminho de um pedido até a sua função

  • O Uvicorn é o servidor: o programa que fica escutando a porta e recebendo os pedidos.
  • O FastAPI decide qual função atende cada pedido e transforma o retorno em JSON.
  • As classes da Aula 8 não mudam. Quem muda é quem chama.

CONCEITOAula 9

Decorador de rota

A linha @app.get("/") em cima da função é um decorador: ela registra a função no FastAPI como a resposta para GET no caminho /. Sem o decorador, a função existe, mas nenhum pedido chega até ela.

exemplo
# GET /produtos
@app.get("/produtos")
def listar_produtos(): ...

# POST /carrinho/itens
@app.post("/carrinho/itens")
def adicionar_item(item): ...

# DELETE /carrinho
@app.delete("/carrinho")
def esvaziar_carrinho(): ...
Pense assimUma etiqueta na porta de cada sala: "pedidos de GET /produtos, entre aqui".

CONCEITOAula 9

Parâmetro de caminho

Um pedaço variável do endereço, escrito entre chaves na rota. O FastAPI recorta esse pedaço e entrega para a função como argumento. Com a dica de tipo int, ele converte o texto em número e valida.

exemplo
@app.get("/produtos/{produto_id}")
def buscar_produto(produto_id: int):
    ...

/produtos/3
    -> produto_id = 3
/produtos/abc
    -> 422: "abc" não é inteiro
       (a função nem chega a rodar)
CuidadoTudo que vem no endereço chega como texto. Sem a dica de tipo, "3" e 3 seriam coisas diferentes.

def buscar_produto(produto_id: int):

CONCEITOAula 9

Parâmetro de consulta

O que vem depois do ? no endereço, em pares nome=valor separados por &. Serve para filtrar, ordenar ou paginar uma coleção. No FastAPI, todo argumento da função que não está no caminho vira parâmetro de consulta.

exemplo

def listar_produtos(
    tamanho: str | None = None,
    preco_max: float | None = None,
):
CuidadoCom valor padrão None, o parâmetro é opcional: /produtos sozinho continua funcionando.

@app.get("/produtos")
def listar_produtos(tamanho: str | None = None, preco_max: float | None = None):
    resultado = []
    for produto_id, produto in CATALOGO.items():
        if tamanho is not None and produto.tamanho != tamanho:
            continue
        if preco_max is not None and produto.preco > preco_max:
            continue
        resultado.append(com_id(produto_id, produto))
    return resultado
  • str | None quer dizer "texto, ou nada". É a dica de tipo para algo opcional.
  • continue pula o produto que não passa no filtro (Aula 4).

CONCEITOAula 9

Corpo do pedido e Pydantic

No POST, os dados vão no corpo do pedido, em JSON. O Pydantic descreve o formato esperado numa classe; o FastAPI usa essa classe para validar o corpo antes de chamar a sua função. Dado inválido nem chega no seu código: volta 422.

exemplo
class ItemPedido(BaseModel):
    produto_id: int
    quantidade: int = Field(gt=0, le=10)

{"produto_id": 1, "quantidade": 3}
    -> passa
{"produto_id": 1, "quantidade": 0}
    -> 422: precisa ser maior que 0
{"produto_id": 1}
    -> 422: faltou a quantidade
Pense assimO formulário com campos obrigatórios: o sistema nem deixa enviar com campo vazio.

RELEMBREAula 6

Invariante e validação na entrada

Uma regra que precisa ser sempre verdadeira para o objeto. Ela é conferida na entrada, no __init__, para nenhum objeto inválido existir.

exemplo
class Produto:
    def __init__(self, nome, preco, tamanho):
        if preco <= 0:
            raise ValueError(
                "preço deve ser maior que zero")
CuidadoA API é a fronteira do sistema com o mundo. O Pydantic faz na fronteira o que o __init__ faz dentro do domínio.

Polimorfismo e contrato

O Carrinho não sabe qual promoção recebeu. Ele chama aplicar, e cada promoção responde do seu jeito. O contrato Promocao garante que toda promoção tem esse método.

exemplo

# ou Cupom(20), ou SemPromocao()

carrinho.total
# 1. soma as peças (subtotal)
# 2. promocao.aplicar(subtotal)
# 3. soma o frete

A API traduz, o domínio decide

API.PY · A FRONTEIRA

Fala HTTP

Recebe o pedido, valida o formato com Pydantic, escolhe o código de status e devolve JSON. Não sabe calcular frete.

LOJA/ · O DOMÍNIO

Fala regra de negócio

Produto, Carrinho e Promocao. Calculam, validam invariantes e não sabem que existe HTTP. Os 30 testes da Aula 8 continuam valendo.

Se amanhã a loja ganhar um app de celular ou um robô no WhatsApp, o domínio é o mesmo. Na Aula 10, essa separação ganha nome: camadas.

Um cliente HTTP de mentira, que vem com o FastAPI. Ele faz pedidos para a aplicação sem abrir porta e sem servidor rodando, e devolve a resposta para o teste conferir o código de status e o JSON.
