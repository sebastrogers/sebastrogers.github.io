A terceira linguagem

Onde o JavaScript roda, e por que ele é diferente do Python que vocês já escrevem.

CONCEITOAula 12

Onde o JavaScript roda

O Python de vocês roda no servidor: a requisição chega, o FastAPI responde, e o usuário nunca vê esse código. O JavaScript roda no navegador da pessoa, na máquina dela, depois que a página chegou. É a única linguagem que o navegador executa.

exemplo
servidor (Python)        navegador (JavaScript)
-----------------        ----------------------
FastAPI, SQLAlchemy      o que acontece na tela
as regras do negócio     clique, digitação, envio
o banco de dados         o que aparece e some

front/app.js  <- o arquivo de hoje
CuidadoTodo JavaScript que vocês escrevem chega inteiro ao navegador e pode ser lido por qualquer um com dois cliques. Senha, token e regra de permissão ficam no servidor, sempre.
CONCEITOAula 12

O console: onde o JavaScript fala com você

O Python avisa no terminal; o JavaScript avisa no console do navegador. Abre com F12 (ou Ctrl+Shift+I) na aba Console. É lá que aparece o que o seu console.log imprime e, em vermelho, todo erro do seu código. A partir de hoje ele fica aberto o tempo todo, ao lado da página.

console do navegador
> console.log("oi")            // você manda imprimir
oi

> 2 + 2                        // dá para testar na hora
4

> document.querySelector("h1")
<h1>Vitrine</h1>

✗ Uncaught TypeError: ... is null   <- vermelho = bug seu
Pense assimO console é o print() do navegador, e também um Python interativo: dá para digitar uma linha e ver o resultado sem salvar arquivo nenhum.
CONCEITOAula 12

let e const

Em Python você atribui e pronto. Em JavaScript toda variável nasce com uma palavra na frente, e essa palavra decide se ela pode ser reatribuída. Regra prática: escreva tudo com const; quando o navegador reclamar, troque aquela linha para let.

exemplo
# Python                   // JavaScript
nome = "Ana"               let nome = "Ana";
nome = "Bia"               nome = "Bia";     // ok

PI = 3.14                  const PI = 3.14;
PI = 3.15   # permitido    PI = 3.15;        // TypeError
Cuidadoconst trava a variável, não o conteúdo. Com const lista = [1, 2], a linha lista.push(3) funciona; o que dá erro é lista = [4].
Fase 1-1 · Dá erro ou não?

Diga o que acontece em cada linha, e por quê.

  • a) const n = 10; n = 11;
  • b) const aluno = { nome: "Ana" }; aluno.nome = "Bia";
  • c) let x; x = 5;
  • d) const lista = []; lista.push("a");

a) erro. Reatribuir a variável é o que const proíbe.

b) funciona. O objeto continua o mesmo; só um campo dentro dele mudou.

c) funciona. let permite declarar agora e atribuir depois.

d) funciona. Mesmo caso do b: a lista é a mesma, só ganhou um item.

FASE 1-2 · CONTEÚDO NOVO

Valores e funções

As comparações que enganam e a forma curta de escrever função.

CONCEITOAula 12

Igualdade: use sempre ===

JavaScript tem dois operadores de igualdade. O == converte os tipos antes de comparar e produz resultados que ninguém espera. O === compara tipo e valor, e é o que corresponde ao == do Python.

exemplo
1 ==  "1"      // true   <- converteu o texto em número
1 === "1"      // false  <- use este

0 == ""        // true
null == undefined  // true

null       // vazio de propósito
undefined  // nunca recebeu valor
CuidadoNão existe caso nesta disciplina em que == seja a escolha certa. Use === e !== sempre.
CONCEITOAula 12

Os seis valores falsos

Em Python, lista vazia e dicionário vazio são falsos. Em JavaScript não. Os valores falsos são exatamente seis: false, 0, "", null, undefined e NaN (Not a Number, "não é um número": o que sobra de uma conta inválida, como Number("abc")). Todo o resto é verdadeiro.

exemplo
if ([]) {
  // ENTRA AQUI. em Python, não entraria
}

const produtos = [];

if (!produtos)              { }  // nunca executa
if (produtos.length === 0)  { }  // o jeito certo
CuidadoPara saber se uma lista está vazia, teste lista.length === 0. O if (not lista) que funciona em Python vira bug silencioso aqui.
CONCEITOAula 12

Função, função de seta e texto com variável

Três novidades de uma vez. A arrow function (função de seta, =>) é a forma curta e sem chaves ela já devolve o resultado. A template string (texto de modelo), entre crases com ${ }, faz o papel da f-string. E função é valor: dá para guardar numa variável e passar como argumento — o mundo 2 inteiro depende disso.

exemplo
# Python                    // JavaScript
def soma(a, b):             function soma(a, b) {
    return a + b              return a + b;
                            }

dobro = lambda x: x * 2     const dobro = (x) => x * 2;

f"R$ {p:.2f}"               `R$ ${p.toFixed(2)}`
Cuidadoconst dobro = x => { x * 2 } devolve undefined. Assim que aparecem as chaves, o return volta a ser obrigatório.
Fase 1-2 · Verdadeiro ou falso?

O if entra ou não entra?

  • a) if ("0")
  • b) if (0)
  • c) if ({})
  • d) if (produtos.length), com a lista vazia

a) entra. É um texto com um caractere; só o texto vazio é falso.

b) não entra. O número zero é um dos seis falsos.

c) entra. Objeto vazio é verdadeiro — ao contrário do Python.

d) não entra. length vale 0, que é falso. Funciona, mas prefira === 0: diz o que você quer dizer.

FASE 1-3 · CONTEÚDO NOVO

Listas e objetos

O que corresponde à lista e ao dicionário do Python, e como percorrer sem escrever laço.

CONCEITOAula 12

Array e objeto

A lista do Python é o array (vetor); o dicionário é o object (objeto), com a chave escrita sem aspas. Os dois se combinam igual ao Python: array de objetos, objeto com array dentro. É assim que a vitrine vai guardar os produtos.

exemplo
# Python                      // JavaScript
len(x)                        x.length
x.append(4)                   x.push(4)
d["nome"]                     d.nome
for p in produtos:            for (const p of produtos)
d.get("x")                    d.x   // undefined, sem erro

const produtos = [
  { nome: "Camiseta", preco: 39.9, tam: "M" },
  { nome: "Calça",    preco: 129.0, tam: "G" }
];
CuidadoLer uma chave que não existe devolve undefined em vez de erro. produto.prceo não quebra nada — e o problema só aparece três linhas depois.
CONCEITOAula 12

map, filter e sort

Onde o Python usa compreensão de lista, o JavaScript chama um método passando uma função. map transforma cada item, filter seleciona, sort ordena. É o uso prático de "função é valor".

exemplo
# Python
nomes = [p["nome"] for p in produtos]
baratos = [p for p in produtos if p["preco"] < 50]

// JavaScript
const nomes   = produtos.map(p => p.nome);
const baratos = produtos.filter(p => p.preco < 50);
const porPreco = [...produtos].sort((a, b) => a.preco - b.preco);
Cuidado[10, 9, 1].sort() devolve [1, 10, 9]: sem função de comparação, sort ordena como texto. Para números, .sort((a, b) => a - b).
Fase 1-3 · Traduza do Python

Como fica em JavaScript?

  • a) [p["nome"] for p in produtos]
  • b) [p for p in produtos if p["tam"] == "M"]
  • c) len(produtos)
  • d) ordenar os produtos do mais barato ao mais caro

a) produtos.map(p => p.nome)

b) produtos.filter(p => p.tam === "M")

c) produtos.length

d) [...produtos].sort((a, b) => a.preco - b.preco) — a cópia evita bagunçar a lista original.

FASE 2-1 · CONTEÚDO NOVO

A página é objeto

O navegador transforma o seu HTML numa árvore que o programa consegue ler e alterar.

CONCEITOAula 12

DOM: a página virou árvore de objetos

DOM é Document Object Model — Modelo de Objetos do Documento. É a tradução do HTML que vocês escreveram na Aula 11 numa árvore de objetos viva na memória do navegador. Mudar o objeto muda a tela na hora; o arquivo no disco continua igual.

exemplo
<main>                          document
  <h1>Vitrine</h1>                └ main
  <section id="vitrine">              ├ h1   "Vitrine"
    <article class="produto">         └ section#vitrine
      ...                                   └ article.produto
    </article>
  </section>
</main>
Pense assimO HTML é a planta da casa; o DOM é a casa construída. Você não reescreve a planta para mover um móvel — mexe na casa. Recarregar a página reconstrói tudo a partir da planta.
Fase 2-1 · Passo a passo

Do arquivo ao comportamento

#O que aconteceQuem faz
1O navegador baixa o index.htmlrede
2Lê o HTML de cima para baixo e monta a árvore do DOMnavegador
3Aplica o estilo.css a cada nó da árvorenavegador

FASE 2-2 · CONTEÚDO NOVO

Mudar a página

Encontrar um elemento, trocar o conteúdo dele e criar elementos novos a partir de dados.

CONCEITOAula 12

Encontrar: querySelector

Dois métodos resolvem quase tudo, e a sintaxe de busca é a mesma do seletor de CSS que vocês aprenderam na Aula 11. querySelector devolve um elemento — o primeiro que casar — ou null. querySelectorAll devolve todos, numa lista.

front/app.js
const titulo  = document.querySelector("h1");
const vitrine = document.querySelector("#vitrine");
const cards   = document.querySelectorAll(".produto");

console.log(cards.length);   // quantos cartões existem
cards.forEach(c => console.log(c.textContent));
Pense assimÉ a busca do CSS, com a mesma escrita: #id, .classe, tag. O que muda é o que você faz depois — lá você pintava, aqui você programa.
CONCEITOAula 12

Alterar e criar

textContent troca o texto. classList liga e desliga classes do CSS — ou seja, o JavaScript aciona o estilo que já existe, em vez de escrever cor na mão. E createElement monta um pedaço de página a partir de dados.

front/app.js
titulo.textContent = "Vitrine da Loja";
card.classList.add("esgotado");      // liga a classe do CSS
card.classList.remove("oculto");

function montarCard(p) {
  const art = document.createElement("article");
  art.className = "produto";
  art.innerHTML = `<h3>${p.nome}</h3><p>R$ ${p.preco.toFixed(2)}</p>`;
  return art;
}

vitrine.innerHTML = "";              // limpa antes de desenhar
produtos.forEach(p => vitrine.append(montarCard(p)));
CuidadoNunca monte innerHTML com algo que o usuário digitou: é a porta de entrada de código estranho na sua página. E limpar antes de desenhar evita a lista duplicada.
Fase 2-2 · Por que deu null?

O código abaixo imprime null e depois quebra. Onde está o erro?

  • <head>
  •   <script src="app.js"></script>
  • </head>  …  <section id="vitrine">
  • e em app.js: document.querySelector("#vitrine").innerHTML = "";

O script rodou antes de o elemento existir.

O navegador lê a página de cima para baixo: no <head>, a section ainda não foi criada.

Correção: mover o <script> para o fim do <body>.

Alternativa: manter no head com o atributo defer, que adia a execução.

FASE 2-3 · CONTEÚDO NOVO

Eventos

O que faz um botão deixar de ser enfeite.

CONCEITOAula 12

addEventListener

Um evento é algo que aconteceu na página: um clique, uma tecla, um formulário enviado. addEventListener (ouvinte de evento) recebe o nome do evento e uma função. A função não roda agora: fica guardada, e o navegador a chama quando o evento acontecer. É a callback (função de retorno).

front/app.js
const botao = document.querySelector("#filtrar");

botao.addEventListener("click", function () {
  console.log("alguém clicou");
});

// mesma coisa, com função de seta
botao.addEventListener("click", () => console.log("clicou"));
CuidadoaddEventListener("click", minhaFuncao()) — com parênteses — executa a função na hora e registra o resultado dela. Passe o nome sem parênteses.
CONCEITOAula 12

click, input, submit — e o preventDefault

Com três eventos dá para fazer o front-end inteiro do projeto. A função recebe um objeto com os dados do evento, por convenção chamado e: e.target é o elemento onde aconteceu e e.target.value é o que foi digitado.

front/app.js
campo.addEventListener("input", (e) => {
  console.log("digitou:", e.target.value);
});

form.addEventListener("submit", (e) => {
  e.preventDefault();      // sem isto, a página recarrega
  const nome = document.querySelector("#nome").value;
  console.log({ nome });
});
CuidadoO comportamento padrão do formulário é recarregar a página, de um tempo anterior ao JavaScript. preventDefault diz "eu cuido disso" — sem ele, o seu código some antes de terminar.
Fase 2-3 · Qual evento usar?

Escolha o evento adequado para cada caso.

  • a) Filtrar a vitrine enquanto a pessoa digita.
  • b) Abrir os detalhes ao tocar no cartão do produto.
  • c) Validar os campos antes de cadastrar um produto.
  • d) Avisar que o campo de preço ficou vazio, só ao sair dele.

a) input: dispara a cada tecla.

b) click: serve para toque no celular também.

c) submit no <form>, com preventDefault — e não click no botão, que deixaria o Enter de fora.

d) blur: dispara quando o campo perde o foco. Existem muitos outros; estes quatro cobrem o projeto.

Fase 3-1 · No editor

front/app.js: a vitrine desenhada por código

front/app.js
const produtos = [
  { nome: "Camiseta básica", preco: 39.9,  tam: "M" },
  { nome: "Calça jeans",     preco: 129.0, tam: "G" },
  { nome: "Moletom",         preco: 159.9, tam: "M" }
];

const vitrine = document.querySelector("#vitrine");

function montarCard(p) {
  const art = document.createElement("article");
  art.className = "produto";
  art.innerHTML = `<h3>${p.nome}</h3>
                   <p>R$ ${p.preco.toFixed(2)}</p>
                   <p>Tamanho ${p.tam}</p>`;
  return art;
}

function desenhar(lista) {
  vitrine.innerHTML = "";
  lista.forEach(p => vitrine.append(montarCard(p)));

A vitrine filtra

Um campo de busca que filtra os produtos enquanto a pessoa digita.

Fase 3-2 · No editor

front/app.js: filtrar enquanto digita

front/app.js
// no index.html, dentro do header:
//   <input id="busca" type="search" placeholder="Buscar produto">

const busca = document.querySelector("#busca");

busca.addEventListener("input", (e) => {
  const termo = e.target.value.toLowerCase();

  const achados = produtos.filter(
    p => p.nome.toLowerCase().includes(termo)
  );

  desenhar(achados);
});
  • O evento input dispara a cada tecla: o filtro acontece enquanto a pessoa digita.
  • toLowerCase dos dois lados faz a busca ignorar maiúsculas.
  • filter devolve uma lista nova; produtos continua intacta — por isso dá para apagar a busca e tudo voltar.
  • Repare: a função desenhar não mudou. Dado e tela separados pagam dividendo já na segunda fase.

O formulário reage

Validar o cadastro antes de enviar — e o produto novo aparecer na vitrine.

Fase 3-3 · No editor

front/app.js: o formulário de cadastro

front/app.js
const form = document.querySelector("#form-produto");
const aviso = document.querySelector("#aviso");

form.addEventListener("submit", (e) => {
  e.preventDefault();

  const nome  = document.querySelector("#nome").value.trim();
  const preco = Number(document.querySelector("#preco").value);

  if (nome === "") {
    aviso.textContent = "Informe o nome do produto.";
    return;
  }
  if (!(preco > 0)) {
    aviso.textContent = "O preço precisa ser maior que zero.";
    return;
  }

  produtos.push({ nome, preco, tam: "M" });
  desenhar(produtos);
  form.reset();
  aviso.textContent = "Produto cadastrado.";
});
  • preventDefault primeiro: sem ele a página recarrega e nada do resto roda.
  • .value sempre devolve texto. Number(...) converte; trim() tira os espaços.
  • !(preco > 0) pega o vazio, o zero, o negativo e o NaN de uma vez.
  • { nome, preco } é atalho para { nome: nome, preco: preco }.
  • A mensagem vai para um elemento na página — nunca para alert.
