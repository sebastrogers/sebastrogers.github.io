01

Onde o JavaScript roda

O Python do seu projeto roda no servidor: a requisição chega, o FastAPI responde, e o usuário nunca vê esse código. O JavaScript roda do outro lado — no navegador da pessoa, na máquina dela, depois que a página já chegou. É a única linguagem que o navegador executa.

Python · servidor
@app.get("/produtos")
def listar(db: Session = Depends(get_db)):
    return db.query(Produto).all()
JavaScript · navegador
const resposta = await fetch("/produtos");
const produtos = await resposta.json();
console.log(produtos.length);

Os dois lados são do mesmo projeto. O Python entrega os dados; o JavaScript decide o que aparece na tela. Essa divisão é toda a Parte B desta trilha.

Pegadinha

Todo JavaScript que você escreve chega inteiro ao navegador do usuário e pode ser lido por ele com dois cliques. Senha, token e regra que decide permissão ficam no servidor, sempre.

Para fixar

Abra qualquer site, pressione F12 e vá na aba Console. Digite 1 + 1 e depois document.title. Esse é o ambiente onde o seu código vai rodar.

02

Variáveis: let e const

Em Python você não declara: atribui e pronto. Em JavaScript toda variável nasce com uma palavra na frente, e essa palavra decide se ela pode ser reatribuída.

Python
nome = "Ana"
nome = "Bia"        # ok

PI = 3.14           # convenção:
PI = 3.15           # nada impede
JavaScript
let nome = "Ana";
nome = "Bia";       // ok

const PI = 3.14;
PI = 3.15;          // TypeError

Regra prática que resolve 95% dos casos: escreva tudo com const. Quando o navegador reclamar porque você precisa reatribuir, troque aquela linha para let. Existe também var, de antes de 2015, com regras de escopo que confundem até quem programa há anos — não use.

Pegadinha

const trava a variável, não o conteúdo dela. Com const lista = [1, 2], a linha lista.push(3) funciona normalmente; o que dá erro é lista = [4].

Para fixar

Por que const aluno = { nome: "Ana" }; aluno.nome = "Bia"; não dá erro nenhum?

03

Tipos, comparação e valores falsos

JavaScript tem dois operadores de igualdade. Um deles converte os tipos antes de comparar e produz resultados que ninguém espera. O outro se comporta como o == do Python.

Python
1 == "1"      # False
1 is None     # False

None          # único "vazio"
JavaScript
1 ==  "1"     // true   (converte!)
1 === "1"     // false  (use este)

null          // vazio de propósito
undefined     // nunca recebeu valor

Use sempre === e !==. Não existe situação na disciplina em que o == seja a escolha certa.

Por que a linguagem converte, afinal? O JavaScript nasceu em 1995 para animar páginas e foi desenhado para não quebrar: diante de uma comparação entre tipos diferentes, ele adivinha em vez de dar erro. A escolha envelheceu mal. O === é o conserto, adotado depois — e o == nunca pôde ser removido, porque quebraria a web inteira.

A segunda diferença é mais sutil. Os valores considerados falsos em JavaScript são exatamente seis: false, 0, "", null, undefined e NaN. Todo o resto é verdadeiro — inclusive lista vazia e objeto vazio, que em Python são falsos.

JavaScript
if ([]) {
  console.log("entra aqui");   // entra! em Python, não entraria
}

const produtos = [];
if (!produtos)            { /* nunca executa */ }
if (produtos.length === 0) { /* este é o jeito certo */ }

Pegadinha

Para saber se uma lista está vazia, teste lista.length === 0. O if (!lista) que funciona em Python nunca é verdadeiro em JavaScript.

Para fixar

Em JavaScript, [] == false vale true, mas [] === false vale false. Com o que você leu aqui, explique as duas linhas.

04

Funções

Python
def soma(a, b):
    return a + b

dobro = lambda x: x * 2

def ola(nome="turma"):
    return f"Olá, {nome}!"
JavaScript
function soma(a, b) {
  return a + b;
}

const dobro = (x) => x * 2;

const ola = (nome = "turma") =>
  `Olá, ${nome}!`;

Três novidades de uma vez. A arrow function (=>) é a forma curta e a mais comum hoje; sem chaves, ela já devolve o resultado, sem precisar de return. A template string, escrita entre crases com ${ }, faz o papel da f-string. E função é valor: dá para guardar numa variável e passar como argumento — é disso que o passo 06 depende inteiro.

Pegadinha

const dobro = x => { x * 2 } devolve undefined. Assim que aparecem as chaves, o return volta a ser obrigatório.

Para fixar

Reescreva lambda x, y: x > y como arrow function.

Arrays e objetos

A lista do Python é o array; o dicionário é o objeto. A tabela abaixo cobre quase tudo o que você vai precisar:

Repare na linha das chaves: no objeto JavaScript, nome não leva aspas. E os dois se combinam exatamente como no Python — array de objetos, objeto com array dentro:

JavaScript
const produto = {
  nome: "Camiseta básica",
  preco: 39.9,
  tamanhos: []
};

produto.tamanhos.push({ tam: "M", estoque: 4 });

console.log(produto.nome, produto.tamanhos.length);   // Camiseta básica 1

Pegadinha

Ler uma chave que não existe devolve undefined em vez de levantar erro. produto.prceo não quebra nada: o programa segue e o bug só aparece três linhas depois, onde você menos espera.

Para fixar

06

Transformar dados

Onde o Python usa compreensão de lista, o JavaScript chama um método passando uma função. É o uso prático do "função é valor" do passo 04.

Python
nomes = [p["nome"] for p in produtos]

baratos = [p for p in produtos
           if p["preco"] < 50]

total = sum(p["preco"] for p in produtos)
JavaScript
const nomes = produtos.map(p => p.nome);

const baratos = produtos.filter(p => p.preco < 50);

const total = produtos.reduce(
  (soma, p) => soma + p.preco, 0);

map transforma cada item e devolve uma lista do mesmo tamanho. filter seleciona e devolve uma lista menor. reduce acumula tudo num valor só — o segundo argumento é o ponto de partida. Nenhum dos três altera a lista original.

O sort é a exceção: ele ordena a lista no lugar. Por isso o [...produtos] abaixo, que faz uma cópia antes de ordenar.

JavaScript
const porNome = [...produtos].sort((a, b) => a.nome.localeCompare(b.nome));

const baratosPrimeiro = [...produtos].sort((a, b) => a.preco - b.preco);
const carosPrimeiro   = [...produtos].sort((a, b) => b.preco - a.preco);

Pegadinha

[10, 9, 1].sort() devolve [1, 10, 9]. Sem função de comparação, o sort ordena como se tudo fosse texto. Para números, sempre .sort((a, b) => a - b).

Para fixar

Escreva a versão JavaScript de [p for p in produtos if p["preco"] > 100].

07

Por que existe assíncrono

O JavaScript do navegador roda em uma linha só de execução. Uma fila única: cada pedaço de código roda do início ao fim antes do próximo começar. Não há duas coisas acontecendo ao mesmo tempo.

A consequência é direta: enquanto o seu código roda, a página não responde. Não rola, não aceita clique, não redesenha. Dá para ver isso no console:

JavaScript · cinco segundos de página travada
const fim = Date.now() + 5000;
while (Date.now() < fim) { }   // segura a fila

// durante esses 5 segundos a aba fica congelada

Agora leve isso para a rede. Buscar os produtos na sua API pode levar 50 milissegundos num wi-fi bom e vários segundos num 3G ruim. Se o JavaScript esperasse parado, a página inteira congelaria a cada requisição.

Daí a saída: pedir e seguir. O navegador tem outras partes, fora da sua linha de execução, e é ele quem cuida da espera. O seu código não espera — ele deixa dito o que fazer quando a resposta chegar, e libera a fila.

Python · no servidor
r = requests.get(".../produtos")
print(r.json())

# a primeira linha bloqueia:
# o programa para até chegar
JavaScript · no navegador
const r = await fetch("/produtos");
console.log(await r.json());

// parece igual, mas a página
// continua respondendo

Parecem a mesma coisa, e esse é exatamente o objetivo do await: ele foi criado para que código assíncrono se pareça com código sequencial. Por baixo, a função é suspensa naquela linha, a fila é devolvida ao navegador, e quando a resposta chega a função volta de onde parou.

Duas regras caem disso, e explicam a maioria dos erros que você vai ver:

  • await só existe dentro de uma função marcada com async.
  • Uma função async devolve sempre uma promise (promessa) — o valor que ainda vai chegar. Quem chamar também precisa de await, ou recebe a promessa em vez do valor.

Pegadinha

await dentro de um forEach não espera nada: o forEach não sabe o que é promessa e segue em frente. Para esperar item a item, use for (const x of lista).

Para fixar

Por que travar a linha de execução por cinco segundos é muito pior no navegador do que no servidor?

08

async, await e fetch na prática

Você já escreveu rotas async no FastAPI, então o raciocínio não é novo: a rede demora, e o programa não fica parado esperando. No navegador isso é visível — enquanto o dado não chega, a página precisa continuar respondendo aos cliques.

JavaScript · buscando dados
async function carregarProdutos() {
  const resposta = await fetch("/produtos");

  if (!resposta.ok) {
    console.error("Falhou com status", resposta.status);
    return [];
  }

  const produtos = await resposta.json();
  return produtos;
}

São dois await: o primeiro espera a resposta chegar, o segundo espera o corpo virar objeto JavaScript. E há uma regra que pega todo mundo: o fetch só falha quando a rede falha. Um 404 ou um 500 chegam como resposta normal — por isso o teste resposta.ok.

JavaScript · enviando dados
await fetch("/produtos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ nome: "Moletom", preco: 159.9, tam: "M" })
});

O corpo vai como texto: JSON.stringify converte o objeto em string, e o cabeçalho avisa ao FastAPI que aquilo é JSON. É o par exato do resposta.json(), que faz o caminho de volta.

Pegadinha

Esquecer o await do .json() devolve uma Promise, não os dados. O sintoma é sempre o mesmo e agora você vai reconhecê-lo: produtos.map is not a function.

Para fixar

Se o fetch não levanta erro em um 404, o que acontece com o código que vem depois dele quando a rota não existe?
