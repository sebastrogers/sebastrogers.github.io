FASE 1-1 · CONTEÚDO NOVO

Modelo é pergunta

Um desenho bem feito mostra ao cliente o que entendemos, e o que ainda não entendemos.

CONCEITOAula 9

Modelo

Uma representação simplificada de algo, feita para um propósito. O modelo deixa de fora o que não importa para aquela conversa. Em requisitos, o modelo ajuda a conferir o entendimento com o cliente antes de construir.

Pense assimA planta de uma casa: ninguém mora nela, mas é nela que o dono percebe que a cozinha ficou longe da garagem.
exemplo
a mesma loja, três modelos:

  mapa de ruas     onde fica
  planta baixa     como os cômodos se ligam
  modelo de domínio  o que o sistema precisa saber

cada um responde a uma pergunta diferente
CuidadoO modelo não é o sistema. Detalhe demais vira projeto de software antes da hora.

O que um diagrama faz que o texto não faz

MOSTRA

O que falta

Uma associação sem multiplicidade vira pergunta: "um pedido pode ter mais de um pagamento?" O texto deixava passar.

RESUME

O todo de uma vez

Dez páginas de casos de uso cabem num diagrama. O cliente revisa em minutos.

ALINHA

Uma linguagem só

A equipe, o cliente e quem chega depois leem os mesmos símbolos, com o mesmo significado.

Sommerville chama isso de modelagem de sistemas: usar modelos na engenharia de requisitos para entender e discutir o sistema antes de existir.

FASE 1-2 · CONTEÚDO NOVO

A UML

Para que todos leiam o mesmo desenho, os símbolos precisam ser padronizados.

CONCEITOAula 9

UML

Unified Modeling Language: uma linguagem gráfica padronizada para modelar software. É mantida pela OMG (Object Management Group); a versão atual é a 2.5.1. Ela define os símbolos, não o processo: cada equipe escolhe quais diagramas usar.

exemplo
UML 2.5.1  ·  OMG, 2017

14 tipos de diagrama, em 2 famílias:
  estrutura       o que o sistema é
  comportamento   o que o sistema faz

na engenharia de requisitos, poucos bastam
CuidadoUML não é obrigatória nem é processo. É vocabulário: use o diagrama que responde à dúvida do momento.

RELEMBREAula 8

Caso de uso

A descrição de como um ator usa o sistema para alcançar um objetivo: cabeçalho, fluxo principal, fluxos alternativos e exceções.

exemplo
UC03 Finalizar compra
Ator: Cliente · Ator secundário: Sistema de pagamento

1. Cliente escolhe "Finalizar compra".
2. Sistema mostra as peças, o frete e o total.
3. Cliente informa o endereço de entrega.
...
8. Sistema registra o pedido e baixa o estoque.
Fase 1-3 · Passo a passo

Achar as classes e as atividades no texto

1
Sublinhe os substantivoscliente, pedido, peça, endereço, pagamento
2
Junte os sinônimos"peça" e "produto" são a mesma coisa
3
Separe classe de atributo"endereço" tem rua e cidade: é classe; "frete" é só um valor: é atributo
4
Circule os verbosinforma, recalcula, envia, registra
5
Verbos viram açõescada verbo é uma caixa do diagrama de atividades

A técnica de achar classes pelos substantivos é descrita por Larman, em Utilizando UML e padrões, no capítulo de modelos de domínio.

Fase 1-3 · Classe ou atributo?

Na loja, cada item vira classe ou atributo?

  • a) cliente
  • b) e-mail do cliente
  • c) endereço de entrega
  • d) total do pedido

a) classe: tem dados próprios e se liga a pedidos.

b) atributo do Cliente: é um valor simples.

c) classe: tem rua, cidade e CEP, e um cliente pode ter vários.

d) atributo do Pedido, ou um valor calculado a partir dos itens.

FASE 2-1 · CONTEÚDO NOVO

Classe e atributo

O primeiro diagrama: o que o sistema precisa conhecer sobre o negócio.

CONCEITOAula 9

Diagrama de classes de domínio

Mostra os conceitos do negócio que o sistema precisa conhecer, os dados de cada um e como eles se ligam. É também chamado de modelo de domínio ou modelo conceitual. Fala a língua do cliente, não a do banco de dados.

exemplo
classe       conceito do negócio
             ex.: Pedido
atributo     dado desse conceito
             ex.: data, situação
associação   ligação entre dois
             ex.: Cliente faz Pedido

sem métodos, sem chave, sem banco
CuidadoSe aparecer id_cliente: INT, o desenho virou modelo de banco. No domínio, a ligação é a linha entre as classes.
Fase 2-1 · Notação

Como se desenha uma classe

  • 1ª parte: o nome, um substantivo no singular, com inicial maiúscula: Produto, não produtos.
  • 2ª parte: os atributos, o que o sistema precisa saber. O tipo, quando aparece, é do negócio: Dinheiro, Tamanho.
  • 3ª parte: as operações. No modelo de domínio, fica vazia ou nem aparece: é assunto do projeto do software.
FASE 2-2 · CONTEÚDO NOVO

Associação e multiplicidade

As linhas entre as classes são onde moram as regras de negócio.

CONCEITOAula 9

Associação e multiplicidade

A associação é uma linha entre duas classes, com um nome que se lê como frase. A multiplicidade, escrita em cada ponta, diz quantos de um lado se ligam a um do outro lado.

exemplo
Cliente  1 ───── faz ───── 0..*  Pedido

lê-se nos dois sentidos:
  um cliente faz zero ou mais pedidos
  um pedido é feito por exatamente um cliente
Pense assimUma regra de negócio desenhada. "Pedido sem cliente pode?" A multiplicidade 1 responde que não.
Fase 2-2 · Notação

Ler multiplicidades

  • Um cliente faz zero ou mais pedidos; cada pedido é de um cliente.
  • Todo pedido contém pelo menos um item.
  • Um pedido pode ainda não ter pagamento.
  • Leitura: 1 exatamente um · 0..1 zero ou um · 0..* zero ou mais · 1..* um ou mais.
Fase 2-2 · Qual multiplicidade?

Complete, perguntando ao cliente da loja

  • Pedido ── ? ── Endereço de entrega
  • Produto ── ? ── ItemPedido
  • Cliente ── ? ── Endereço

Pedido 0..* — 1 Endereço: cada pedido vai para exatamente um endereço; um endereço pode receber vários pedidos.

Produto 1 — 0..* ItemPedido: um produto aparece em muitos itens, ou em nenhum ainda.

Cliente 1 — 1..* Endereço: se a loja exigir ao menos um endereço. Se não exigir, 0..*. Quem decide é o cliente: é uma pergunta de requisito.

FASE 2-3 · CONTEÚDO NOVO

O modelo da loja

Tudo junto: classes, atributos, associações e um caso de "é um tipo de".

CONCEITOAula 9

Generalização

Uma relação de "é um tipo de": a classe específica tem tudo da geral e acrescenta o que é só dela. Desenha-se com uma seta de triângulo vazio apontando para a classe geral.

exemplo
Camiseta ──▷ Produto
Calça    ──▷ Produto

Camiseta tem nome, preço, tamanho (de Produto)
         e manga (só dela)
CuidadoUse só quando a classe específica tem dados ou regras próprias. Cor da roupa não vira subclasse: é atributo.

Fase 2-3 · Revisar o modelo

Perguntas que o modelo provoca no cliente

  • Pedido 0..1 Pagamento: um pedido pode ser pago em duas formas, metade no cartão e metade no Pix?
  • Cliente 1..* Endereço: dá para comprar sem cadastrar endereço, para retirar na loja?
  • ItemPedido.preço unitário: por que guardar o preço no item, se o Produto já tem preço? (o preço muda; o pedido antigo, não)
  • Cada resposta do cliente vira requisito ou regra de negócio no DDR.
FASE 3-1 · CONTEÚDO NOVO

Ação e fluxo

O segundo diagrama: o caso de uso como um fluxo de passos.

CONCEITOAula 9

Diagrama de atividades

Mostra um processo como uma sequência de ações ligadas por fluxos, do início ao fim, com os desvios e os passos em paralelo. É o caso de uso (ou o processo de negócio) desenhado.

exemplo
início ● → [ação] → [ação] → ◇ decisão
                          ├ [sim] → [ação] → ◉ fim
                          └ [não] → volta

cada ação: verbo + objeto
"Recalcula o frete", "Envia a cobrança"
Pense assimUm fluxograma, com regras: os mesmos símbolos para todo mundo e uma raia para cada responsável.

FASE 3-2 · CONTEÚDO NOVO

Decisão, paralelo e raias

O que faz o diagrama de atividades valer mais que uma lista de passos.

CONCEITOAula 9

Decisão e guarda

O losango divide o fluxo em caminhos. Cada saída tem uma guarda entre colchetes, uma condição que diz quando aquele caminho é seguido. As guardas de uma decisão precisam cobrir todos os casos, sem sobrepor.

exemplo
◇ pagamento
├ [aprovado]  → Registra o pedido
└ [recusado]  → Escolhe a forma de pagamento

as exceções e alternativos do caso de uso
viram as saídas das decisões
CuidadoGuardas que se sobrepõem, como [valor > 100] e [valor > 50], deixam o caminho ambíguo: é defeito de requisito.
CONCEITOAula 9

Paralelo e raias

A barra de bifurcação abre caminhos que acontecem ao mesmo tempo; a barra de união espera todos terminarem. As raias (partições) dividem o diagrama por quem faz cada ação: um ator, um sistema ou um setor.

exemplo
        ┌→ Registra o pedido ┐
━━━━━━━━┤                   ├━━━━━━━━
        └→ Baixa o estoque   ┘

raias: Cliente | Sistema | Pagamento
Pense assimDuas pessoas embalando e emitindo a nota ao mesmo tempo: o pacote só sai quando as duas terminam.
